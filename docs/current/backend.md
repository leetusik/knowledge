## Stack

- Language/runtime: Python 3.12.
- Framework: FastAPI + uvicorn.
- Package manager: uv — **virtual project** (`[tool.uv] package=false`, no `[build-system]`): deps only, never built/installed (matches the container's `--no-emit-project`). `[tool.pytest.ini_options] pythonpath=["."]` lets `import server` resolve without installing.
- Server entrypoint: `server.main:app` (`uvicorn server.main:app`), **single worker** (load-bearing — see invariants).
- Deps: `fastapi`, `uvicorn`, `pyyaml`, `google-genai` (embeddings, reusing changple5's pin); **(P10)** `sqlalchemy` (2.0), `psycopg[binary]` (async psycopg3 driver), `alembic`, `argon2-cffi`, `greenlet`; dev: `pytest`, `httpx`.
- **(P10) Async control plane in a sync app.** The accounts plane is `async` (async SQLAlchemy 2.0 + `postgresql+psycopg`) and lives **alongside** the existing sync content endpoints in the one FastAPI app. The async-vs-sync integration Open Question was resolved to **async SQLAlchemy + psycopg3** (not asyncpg): a single worker means no async-throughput requirement, so the choice was made for the cleaner integration. The engine is a **lazy singleton** created on first use and disposed in the app lifespan; `DATABASE_URL` unset → no engine is ever created (accounts dormant).

## Module Layout (`server/`)

- **`config`** — env-at-call-time settings (no import-time caching, so tests retarget per call): `KB_ROOT` (default cwd), `docs_root` (=`KB_ROOT/docs`), `KB_DB_PATH` (default `KB_ROOT/data/kb.sqlite3`), `KB_PUBLIC_BASE_URL` (default `http://localhost:8765`, the viewer origin for response `url`s), `KB_API_TOKEN` (unset by default), `KB_GIT_COMMIT` (default true), plus (P4) `gemini_api_key` (`GOOGLE_API_KEY` preferred → `GEMINI_API_KEY` fallback; `None` = semantic search off), `embedding_model` (`GEMINI_EMBEDDING_MODEL`, default `gemini-embedding-2-preview`), `embeddings_enabled`, and `startup_reindex_enabled` (`KB_STARTUP_REINDEX`, default true), plus **(P24)** `git_timeout_s` (`KB_GIT_TIMEOUT_S`, default **60** seconds — the wall-clock cap on *every* git subprocess; unparseable or non-positive values fall back to 60, so the cap can never be switched off).
- **`db`** — `connect(path=None)` (WAL, `sqlite3.Row` factory, `PRAGMA foreign_keys=ON`, idempotent DDL + an idempotent `PRAGMA table_info`→`ALTER TABLE` migration for the P4 `related` column, creates parent dirs); `upsert_document` (ON CONFLICT(rel_path); preserves `created_at`, refreshes `updated_at`; now threads `related`), `get_document`, `get_document_by_path`, `list_documents` (newest-first, tag via `json_each`), `count_documents`, `delete_document_by_path` (relies on the FTS `AFTER DELETE` trigger + the embedding FK cascade — no extra cleanup code). P4 aggregations: `list_tags(conn, project=None)` and `list_projects(conn)` (both `json_each`/`GROUP BY`, pre-ordered for display). P4 embedding cache: `document_embeddings` DDL + `upsert_embedding`, `get_embedding`, `get_embedding_hashes`, `get_all_embeddings`, `delete_orphan_embeddings`. Reads JSON-decode `tags` and `related` to lists.
- **`documents`** — conventions + write composition: `slugify`; validators `validate_project/tags/slug/date` (raise `ConventionError`; `FrontmatterError` is a subclass — both map to 422), plus P4 `validate_related` (list of relative, no-`..`, ≥2-part, `.md` rel_paths; dedup order-preserving; `ConventionError` otherwise); `rel_path`; **hand-rolled byte-exact** `serialize_frontmatter` (title via `json.dumps(ensure_ascii=False)`; bare date; tag list; optional two-space-indented `related:` block between `tags:` and `source:`, emitted only when non-empty so absent-`related` output stays byte-identical; `source:` map) with `parse_frontmatter`; `insert_recent_bullet` / `update_recent_index` and their P4 inverses `remove_recent_bullet` (pure — drops the line carrying `](<rel_path>)`) / `remove_from_recent_index` (I/O; idempotent, no write when nothing matched); `write_document_file` (now takes optional `related`; returns the body **exactly as reindex would store it** — no drift); P4 `sanitize_source_repo` (local paths → basename, URLs pass through, empty for null). **P7 (F1)** `project_landing_content(project)` (the minimal landing body: H1 = project name + a one-line description, **no YAML frontmatter** — so it stays a *non-doc*: on `graph_hook`'s `_SKIP_NAMES`, excluded from `discover_projects` doc-counting and from `check_graph`'s `fs_count`, existing only to produce the per-project `site/<project>/index.html`) and `ensure_project_landing(docs_root, project) -> bool` (writes it iff `docs/<project>/index.md` is absent; returns `True` when it created one, never overwriting an existing hand-written or auto-created landing).
- **`embeddings`** (P4, new) — the **only** module that talks to Gemini (`google-genai`, model `gemini-embedding-2-preview`): `embed_texts(texts, *, kind, retries)` (one request per text — the SDK does not batch; bounded 429 backoff used only on the reindex path), `document_input`, `content_hash` (sha256 of model + `title\n\nbody` truncated to `MAX_INPUT_CHARS=20000`), `pack_vector`/`unpack_vector` (L2-normalized float32 BLOBs, no numpy), `cosine`, and `EmbeddingError`. Vectors are 3072-dim.
- **`search`** — `build_match_query(q)` double-quotes each whitespace token (doubling internal `"`) and (P4) prefix-expands CJK/Hangul/Kana tokens to `"tok"*` so those scripts are word-searchable at the query layer without a tokenizer change; `search(conn, q, *, project, tag, limit=10, offset=0, raw=False)` re-ranks the **full** match set in Python — weighted BM25 (8/4/1) fused with an exp-decay recency signal from `d.date` (`score = bm25 + RECENCY_WEIGHT·recency`; `HALF_LIFE_DAYS=90`, `RECENCY_WEIGHT=0.5`) — then, when embeddings are enabled and the query embeds, fuses a cosine vector ordering (over `get_all_embeddings`) via **RRF** (`RRF_K=60`) over the union of both lists. Returns `{results, total, mode}` (`mode` = `"hybrid"`/`"bm25"`; `total` = match/fusion count); `signals` = `{bm25?, recency, vector?}`; `offset`/`limit` slice the composed order. `raw=True` and the no-vector/degraded paths stay exact BM25 behavior; a raw syntax error re-raises as `SearchQueryError` (→ 400).
- **`gitops`** — `GitError(command, stderr)`; `add(paths, *, root)` = `git -C <root> add -- <paths…>` (only the touched paths — **never `-A`**); `commit(msg, *, root, co_authored_by=None)` → `rev-parse HEAD` (optional second `-m` trailer); `push(*, root, remote="origin", branch="main")` (P8) = `fetch` → `rebase <remote>/<branch>` → non-force `push HEAD:<branch>`, returning the final **published** head and aborting any in-progress rebase on failure (the local commit is always preserved). Every failure (nothing-to-commit, missing identity, unsafe dir, a rejected push) raises `GitError`. **(P24) every subprocess goes through `_run(..., timeout=config.git_timeout_s())`** — including the failure-path `rebase --abort`, which swallows its own timeout so it cannot mask the real error — and a `subprocess.TimeoutExpired` (the child is killed first) surfaces through the **same `GitError` channel** as a non-zero exit, since callers already treat that as "not published, keep the write". This is what makes the module safe to call from the publish worker, which holds `WRITE_LOCK` while it runs.
- **`reindex`** — library fns + `python -m server.reindex [rel_path]` CLI; `reindex()` walks `docs/<subdir>/**/*.md`, upserts present rows, removes vanished ones (`RESERVED_DIRS = {"current","versions"}` excluded; malformed → `skipped[]`), then runs `_sync_embeddings(conn)` (content-hash-cached, per-doc incremental embed+upsert, orphan/model-mismatch cleanup — best-effort, never fails the reindex) and folds its report under `embeddings:`. P4 `reindex_path(rel_path, conn=None, docs_root=None)` validates the rel_path shape (ValueError on absolute/`..`/<2-part/reserved/non-`.md`) and indexes or deletes a single path, running the same embedding sync. `_index_file` reads `meta.get("related")` and sanitizes `source.repo` leniently. Never runs git.
- **`main`** — FastAPI `app`; per-request `get_conn()` dependency; `require_bearer` dependency; `_public_doc` response shaper (drops `tags_text`; `markdown` only on single-doc fetches; passes through `related`); a P4 `lifespan` that runs a full `reindex()` on boot when `startup_reindex_enabled()` (drift self-heal, printing `[kb-api] startup reindex: …`); module-level `WRITE_LOCK = threading.Lock()` wrapping the write critical section of `POST /api/documents` **and** the P4 shared `_delete_document` helper (reused by both DELETE routes: file remove → Recent-bullet removal → `db.delete_document_by_path` → scoped commit, same no-rollback contract). `create_document` validates/drops-self-ref `related`, sanitizes `source_repo`, and **(P24) queues both the publish push and the embed on the after-response worker** — `publish.submit(...)` outside `WRITE_LOCK`, since the push task re-takes it (any failure is logged by the worker, never affecting the 201). **P7 (F1):** inside `WRITE_LOCK`, right after `write_document_file`, it calls `ensure_project_landing(docs_root, project)`; when that returns `True` the scoped commit stages a **third** path (`docs/<project>/index.md`) and the 201 body carries `landing_created:true` (else the usual 2 paths, `landing_created:false`). The DELETE path is deliberately unchanged: deleting a project's last real doc leaves the auto-landing behind, but `discover_projects` no longer lists a project whose only file is `index.md`, so the gate stays satisfied — no delete-side cleanup is warranted. Adds the open `GET /api/tags`/`GET /api/projects` reads and the `ReindexIn`-bodied `POST /api/reindex`.

### Accounts control plane (P10, new)

- **`persistence/`** — the ORM foundation. `base.py`: a `NAMING_CONVENTION` + declarative `Base` (stable Alembic constraint names). `models.py`: the **six** accounts tables (`UserModel`, `TenantModel`, `TenantMemberModel`, `ProjectModel`, `ProjectCredentialModel`, `AuthTokenModel`) — UUID PKs, tz-aware `created_at`; ownership is the `tenant_members` join (no owner column on `tenants`). `engine.py`: `get_engine`/`get_session_maker`/`dispose_engine` — lazy async singletons over `config.database_url()`; unset → `get_engine()` raises `RuntimeError` (dormant). Alembic lives at repo root (`alembic.ini` + async `alembic/env.py`, initial migration `0001_accounts_tenancy`); migrations run **explicitly** (`alembic upgrade head`), never on boot.
- **`accounts/`** — the layered accounts service (ported from the `vocky` reference): `security.py` (argon2id `hash_password`/`verify_password`, `generate_opaque_token` = `secrets.token_urlsafe(32)`, `sha256_hex`); `types.py` (transport-neutral `@dataclass` records — credential/session records **omit `token_hash`** so hashes never cross the transport boundary); `repository.py` (the **sole** ORM boundary — `add → flush → refresh → *Record`, never commits); `service.py` (owns transactions + domain errors `AccountsPersistenceError`/`AccountsReadError`/`DuplicateEmailError`; `create_tenant_with_owner` is the atomic signup primitive). `auth.py`: the reusable `require_user(request) -> AuthContext(user, tenant)` FastAPI guard (bearer → `sha256_hex` → active session token → user → `tenants[0]`) + `extract_bearer_token` + the generic-401 `auth_error_handler`. Entrypoint: `get_accounts_service()`.
- **`auth_api.py`** / **`app_api.py`** — two `APIRouter`s mounted by one `include_router` line each in `main.py`. `auth_api`: `/auth/signup|login|logout|me` (30-day opaque session tokens, enumeration-safe generic 401s, hash-free serializers). `app_api`: `require_user`-guarded `/app/*` (tenant, projects, per-project `vk_` credentials), all scoped to `ctx.tenant.id`; `_load_scoped_project` returns 404 for both missing and cross-tenant so existence never leaks. `vk_` mint recipe: `key=f"vk_{generate_opaque_token()}"`, `token_prefix=key[:12]`, `token_hash=sha256_hex(key)`, raw key returned once.
- **`api_auth.py`** — the `/api/*` two-mode credential resolver. `_tenant_mode()` switches per-call on `DATABASE_URL`. Legacy mode reproduces the old `require_bearer`/`require_read_bearer` guards byte-for-byte (returns the shared `_LEGACY` context, `tenant_id=None`). Tenant mode maps a bearer → `ApiAuthContext(tenant_id, project_id, is_public)`: exact `KB_API_TOKEN` → tenant #1 (the pinned master, via `get_tenant_one_id()`), a `vk_` key → its project's tenant (+project), a session token → the user's `tenants[0]`; unresolvable/absent → generic 401. `get_tenant_one_id()` resolves tenant #1 from `KB_OPERATOR_EMAIL` (normalized `.strip().lower()` — **P10.F1**, casing-tolerant) and caches **on success only** (so the operator seeded after boot still resolves). `is_public` marks legacy/tenant-#1 callers (→ `docs/`) apart from every other tenant (→ `tenants/<uuid>/`).
- **Per-tenant content routing in `main.py`** — `_tenant_root(ctx)` (public → `config.docs_root()`, else `KB_ROOT/tenants/<uuid>/`), `_tenant_db_id(ctx)` (write stamp: `''` legacy, else the uuid), `_tenant_filter(ctx)` (read scope: `None` legacy, else the uuid string). Git publish + project landing + Recent index run **only** for the public root (`ctx.is_public`); every read/search/list/by-id/by-path/delete query passes `tenant_id=_tenant_filter(ctx)`. `POST /api/reindex` is now `async`, resolves tenant #1 for the `docs/` walk, and stays operator-only (a `vk_` key → 401). `reindex.py` re-derives `tenant_id` from the content root so a rebuilt DB re-populates it from the path alone (hard coupling), and its vanished-row cleanup is tenant-scoped (one tenant's reindex never deletes another's rows).
- **`seed.py`** (`python -m server.seed`) — idempotent, Postgres-only operator/tenant/project seed built on `AccountsService`: creates the operator user (argon2id, race-safe on `DuplicateEmailError`) + tenant #1 (`create_tenant_with_owner`) + a `projects` row per **live `docs/` project derived from the tree** (reindex's `_FILENAME_RE` + `RESERVED_DIRS`, `project = rel.parts[0]`) — never hardcoded, so seeded names line up with `documents.project`. No `vk_` seeded (the master bearer covers tenant #1). `config.operator_email()`/`operator_password()` are the new seed-only settings.

### Usage-metering plane (P11, new)

- **`usage/` package (transport-neutral, mirrors the accounts layering).** `types.py`: the shared `EVENT_*` constants (`document.created`/`document.deleted`/`search` — imported by the hook and the read API, never re-declared) + the `@dataclass` records (`RecordUsageEvent` input; `UsageMetrics`/`UsageTotals`/`UsageDailyCount` aggregate). `repository.py`: the sole ORM boundary — `insert_usage_event` (add+flush, never commits) and `get_usage_metrics`, the derive-on-read aggregate (one grouped SELECT over `func.date(func.timezone("UTC", occurred_at))`, per-`event_type` `func.count().filter(...)`, window filtered half-open `occurred_at >= start AND occurred_at < end`; days zero-filled by `_iter_days` — which excludes a trailing exactly-midnight `end` day — and totals summed in Python). `service.py`: `UsageService` owns the session/transaction and domain errors — `record_event` runs on its **own isolated transaction and raises** `UsagePersistenceError` on failure (so best-effort lives at the call site, not buried), and `get_usage_metrics` surfaces `UsageReadError`. Entrypoint `get_usage_service()`.
- **`usage/metering.py` — the content-plane → usage-events bridge.** `UsageHint{tenant_id, event_type, project_name, project_id, credential_id}` is what a metered handler stashes on `request.state.usage`; `async record_usage(hint)` is **best-effort** (a broad `try/except Exception` + `logging.warning(exc_info=True)` around S1's raising `record_event`), so a metering failure never surfaces into the observed request. It resolves project attribution (`project_name` → tenant project UUID via `get_project_by_name`, else the `vk_` caller's bound `project_id`, else tenant-level NULL), records the event, then stamps `last_used_at` — **on the metered event only**, never in the resolver (stamping in the resolver would write on every read, contradicting "open reads stay fast"). A `vk_` key used only for reads therefore reflects its last write/search.
- **The stash + async middleware seam (`usage_metering` in `server/main.py`).** The metered content handlers (`create_document`, `delete_document`/`_by_path`, `search`) are **sync `def`** (they hold `WRITE_LOCK` over a sqlite critical section) and cannot `await` a Postgres write, and the event type + success status are only known *after* the handler runs. So each stashes a `UsageHint` on its **success path only**; a single `@app.middleware("http")` reads it off `request.state` after `call_next` and calls `record_usage` **iff** a hint is present, `hint.tenant_id is not None`, **and** the response is **2xx**. Error paths (401/404/409/422/400) raise before the stash, so only successes are metered; legacy mode carries `tenant_id=None` so the guard skips and no engine is created (inert). Awaiting in the middleware keeps metering synchronous w.r.t. the client while the sync handler never blocks on Postgres.
- **Supporting additions.** `ApiAuthContext.credential_id: UUID | None` (`server/api_auth.py`), set **only** in the `vk_` branch of `_resolve_tenant_bearer` (master/session leave it `None`), carried so the middleware can stamp the credential. `AccountsService.get_project_by_name(tenant_id, name)` (repository + service) — tenant-scoped, **oldest-wins** (`ORDER BY created_at, id LIMIT 1`, since names aren't unique per tenant) — for name→UUID attribution. `touch_credential_last_used` (built in P10, unwired) is now called by `record_usage`.
- **`usage_api.py` (read router).** `GET /app/usage` + `GET /app/projects/{id}/usage` over `get_usage_metrics`, `require_user`-guarded and tenant-scoped, reusing `_load_scoped_project`/`serialize_project`/`serialize_credential` from `app_api`. It only reports — no metering, no persistence. See api.

### HTML explainer document format (P16, new)

P16 adds a standalone self-contained HTML explainer as a first-class content-plane format, additive across the write path, storage, extraction, indexing, and a raw read route.

- **The body rule (the core invariant — identical on write and reindex).** `body` = the on-disk content minus its frontmatter block. Then: **md** → DB `markdown` = body, `raw_html` = NULL, `format` = `'md'`; **html** → DB `markdown` = `extract_html_text(body)`, `raw_html` = body, `format` = `'html'`. Both `create_document` and `reindex._index_file` apply this same rule against the same normalized body string, so a **fresh-DB reindex reproduces the write-path row byte-for-byte** (`markdown` **and** `raw_html`) — proven at review (wipe `kb.sqlite3` + `reindex()` → identical rows). Because the DB `markdown` column always holds readable text, FTS5 / `snippet()` / embeddings (`document_input`) run **unchanged**.
- **`documents.py` additions.** `rel_path(project, date, slug, fmt="md")` → `.html` for html (default keeps every existing caller byte-identical); `validate_related` accepts `.md` **or** `.html`; `serialize_html_frontmatter`/`parse_html_frontmatter` — a **leading `<!--kb\n<yaml field lines>\n-->\n` HTML-comment frontmatter block** (the browser ignores it; reindex re-derives title/date/tags/related/source from it) parallel to the `---`-fenced markdown frontmatter (factored to a shared `_frontmatter_inner_lines`, verified byte-identical to the pre-P16 markdown output); `extract_html_text(html)` — a stdlib `html.parser.HTMLParser` subclass that drops `script`/`style`/`template`/`noscript` content, inserts coarse block-boundary newlines, and whitespace-normalizes (**no new deps**); `write_document_file(..., fmt="md")` writes `serialize_html_frontmatter + "\n" + _normalize_body(body)` for html and re-parses its own output (self-roundtrip preserved). The md write path is byte-identical.
- **`db.py`.** `_SCHEMA` `documents` gains `format TEXT NOT NULL DEFAULT 'md'` and nullable `raw_html TEXT`; `init_db` back-fills both via the existing PRAGMA-guarded `ALTER TABLE ADD COLUMN` pattern (the `related` precedent); `upsert_document` gains keyword-only `format="md"` / `raw_html=None`, threaded through the INSERT columns **and** the `ON CONFLICT … DO UPDATE SET`. The FTS definition is untouched.
- **`main.py`.** `DocumentIn.format: Literal["md","html"] = "md"` (bad value → free 422); `create_document` applies the body rule, threads `format`/`raw_html` into the upsert, and adds an additive `format` to the 201 response. The `_INTERNAL` drop-set gains `raw_html` (never in `/api` JSON; `format` **is** exposed). Embeddings input already keys on the stored extracted text — unchanged.
- **`reindex.py` / `seed.py` widening.** `_FILENAME_RE` → `\.(md|html)$`; `_walk_root` globs a merged sorted `*.md` + `*.html`; `reindex_path`'s extension check widens to `.md`/`.html`; `_index_file` branches on extension → the matching frontmatter parser + the same body rule → upsert with `format`/`raw_html`. Malformed comment-frontmatter takes the same skip-with-reason path as md. `seed._discover_projects` auto-widens via the shared `_FILENAME_RE`, so an HTML-only project is discovered. The delete path is `rel_path`-keyed → already format-agnostic.
- **`documents_api.py` — the raw route.** `GET /app/documents/{doc_id}/raw` (`require_user`, tenant-scoped, `_DROP` gains `raw_html`): **404** when missing / cross-tenant / `format != "html"` / empty `raw_html`; else `Response(raw_html, media_type="text/html; charset=utf-8")` with `Content-Security-Policy: sandbox allow-scripts; frame-ancestors 'self'` + `X-Frame-Options: SAMEORIGIN` + `X-Content-Type-Options: nosniff` + `Cache-Control: no-store`. The served bytes exclude the comment-frontmatter (start at `<!DOCTYPE html>`). Unmetered. The XSS-containment rationale is in **architecture**; the web relay in **frontend**.
- **Accepted quirk (recorded, not engineered around).** Overwriting a slug with the other format yields a **different `rel_path`** (the extension differs), so an `.md` and an `.html` file can coexist for the same project/date-slug; delete is per-`rel_path`, so this is consistent.

### Accounts v2: org-level credentials + get-or-create (P18, new)

P18 makes org-level `vk_` keys honest and projects get-or-create, all on the P18.S1 schema (`0003`; see data). Additive across the accounts service, the resolver, and the write path.

- **`provision_signup(user_id)` — the shared signup primitive** (`server/accounts/service.py`). Creates tenant `"default"` + an `owner` `tenant_members` row + project `"default"` in **one transaction**, returning `(TenantRecord, TenantMemberRecord, ProjectRecord)`. Constants `DEFAULT_ORG_NAME` / `DEFAULT_PROJECT_NAME` (both `"default"`) live beside it. Signup (`server/auth_api.py`) and the **fresh-DB** seed (`server/seed.py`) both call it, so signup and a first-boot seed can't drift; `create_tenant_with_owner` is retained for bare-tenant callers. **Seed no longer renames an existing tenant** — an already-seeded prod tenant #1 keeps its name and only gains a `"default"` project lazily (via get-or-create). Signup's response gained an additive `project` field alongside `tenant`.
- **Resolver reads `cred.tenant_id` directly** (`server/api_auth.py` `_resolve_tenant_bearer`). An **org-level** key (`project_id NULL`) resolves to `ApiAuthContext(tenant_id=cred.tenant_id, …)` with **no project query**; a **project-bound** key keeps the vanished-project existence guard (`get_project(cred.project_id)`) and carries `project_id` for attribution. Master-token + session paths are untouched. This is **no trust-boundary change** — enforcement was already tenant-wide; org-level keys make it honest (see security).
- **New service/repository methods.** `get_or_create_project(tenant_id, name)` — `get_project_by_name` first, else `create_project` + commit, **race-safe** against the new `UNIQUE(tenant_id, name)` (catch `IntegrityError` → rollback → re-read). `list_org_credentials(tenant_id)` — `WHERE tenant_id = … AND project_id IS NULL`, oldest-first. `serialize_credential` is now **NULL-safe** (`project_id: null` for org keys) — it is the shared serializer `usage_api` also imports.
- **Write-path get-or-create via an async dependency.** `ensure_registry_project(body, ctx)` (async) runs `get_or_create_project(ctx.tenant_id, body.project)` and returns the id; it is wired as a FastAPI `Depends` in front of the sync, `WRITE_LOCK`-holding `create_document` (FastAPI parses the body once and caches `resolve_api_write`, so the dep runs once, before the handler — the seam that lets a Postgres write precede the sqlite critical section). An unregistered `body.project` now always leaves a `projects` row (idempotent, harmless even if the handler later 409/422s). `POST /app/projects` was folded into `get_or_create_project` too (a duplicate name → 201 existing row, closing the latent dupe-500 the new UNIQUE would otherwise cause). `server/usage/metering.py` is **unchanged** — its name-first `get_project_by_name` lookup now always finds the row the write get-or-created.

### Public read surface + visibility bridge (P19, new)

P19 adds per-project visibility (Postgres) and the product's first anonymous read path (the SQLite content plane), bridged per read. Additive across the accounts service, two read routers, `db.py`, and the save-URL build. All `server/**` edits are byte-mirrored to `plugin/templates/kb/`.

- **`projects.visibility` through the accounts layer (P19.S1).** `ProjectModel.visibility` (`Text NOT NULL default "private"`, `server_default=text("'private'")`), `CreateProject.visibility="private"` (defaulted, so `provision_signup`/`get_or_create_project` keep making private rows untouched) + required `ProjectRecord.visibility`; `serialize_project` (canonical `app_api.py` + mirrored `auth_api.py`) and `dashboard_api.py`'s rollup row gain `"visibility"`. New `set_project_visibility(project_id, visibility) -> ProjectRecord | None` (repository load-mutate-flush-refresh, service commits) backs **`PATCH /app/projects/{project_id}`** (`require_user`; `_load_scoped_project` → 404 missing/cross-tenant; `Literal["private","public"]` → 422). See **api**/**data**.
- **`optional_user` — the optional-identity dependency (`server/accounts/auth.py`).** Resolves a bearer **exactly** as `require_user` (same extraction, session/user/tenant lookup, best-effort `last_used_at` stamp) but **returns `None` instead of raising** on every miss path — it never raises. Deliberate contract shift: an unresolvable token on a private doc now yields the anonymous 404, not a 401 (leaks strictly less; the BFF pre-verifies sessions). Only `GET /app/documents/{id}` + `/raw` + `GET /app/graph` swapped to it; `/app/documents` (list) + `/app/search` stay `require_user`.
- **Doc read resolution (`documents_api._resolve_readable_doc`).** Two ordered gates: (1) **member fast-path** — with a `ctx`, today's scoped `get_document(..., tenant_id=<caller>)`; a hit serves byte-preserved and never touches the accounts service; (2) **public path** (no `ctx`, or a scoped miss — covers anonymous **and** cross-org): a **legacy-mode guard** (`config.database_url() is None` ⇒ 404 before touching the absent accounts service, so the single-tenant template stack never 500s and never exposes a public path); an unscoped lookup; a missing row ⇒ 404; a registry-less owner (`tenant_id` empty / `''` legacy sentinel / unparseable UUID) ⇒ 404 (such rows are never public); then `get_project_by_name(owner_uuid, row["project"])` must exist **and** be `visibility == "public"` — else 404. `/raw` additionally keeps its `format=="html" and raw_html` 404 branch and the byte-identical P16 sandbox headers.
- **Graph public path (`graph_api.graph`).** `org` absent or `== ctx.tenant.id` ⇒ the pre-P19 whole-corpus member call (anonymous bare call raises the same generic 401). Otherwise the **public view**: legacy-mode guard ⇒ 404; `public_names = [p.name for p in list_projects_for_tenant(org) if p.visibility=="public"]`; empty (also a nonexistent org) ⇒ 404 `"graph not found"` (no existence leak); else build over the allowlist. The `project` narrowing param is ignored on the public path.
- **The visibility bridge predicate (`db._filtered`).** `_filtered`/`list_documents`/`count_documents` gained an optional `projects: Sequence[str] | None = None` project-name allowlist → `project IN (?,…)`. Default `None` leaves every existing caller byte-identical; an **empty** list **fails closed** (`WHERE … 0`, matches nothing) — so even if the graph route's empty-set 404 were ever bypassed, the predicate never opens up on an empty allowlist. This is the per-read Postgres(name+visibility)→SQLite(name string) bridge, feasible because the projects table is tiny and the graph is bounded by `MAX_DOC_NODES`.
- **Mode-aware save `url` (`main.py:592-601`).** The single build site now branches on **`ctx.tenant_id`** (never `is_public`): tenant mode → `f"{config.public_base_url()}/documents/{doc_id}"` (the S3 direct doc page); legacy/single-tenant → the unchanged mkdocs `{project}/{date}-{slug}/`. `public_base_url()` already strips a trailing slash (no redundant `.rstrip`); the frozen 201 key set is untouched (value changed, `url` key unchanged). `config.public_base_url()`'s docstring was reworded to the mode-aware meaning (app origin in tenant mode / mkdocs origin in legacy). The CLI un-hides this `url` on `save`, and both `SKILL.md` copies note it is shareable when public.

### Member delete on the `/app` plane (P21, new)

P21 gives the web app a hard delete. The route is new; the **delete logic is not** — it is `main.py`'s existing `_delete_document`, reached without extraction and without a second lock. `server/main.py` was not modified (verified at the P21 review), and both edited files (`server/documents_api.py`, `tests/test_documents_api.py`) are byte-mirrored into `plugin/templates/kb/`.

- **`DELETE /app/documents/{doc_id}` (`documents_api.py`).** `require_user`, **no** `conn` dependency, **no** `request.state.usage` — so it is unmetered by construction, unlike the `/api` DELETE routes which stash an `EVENT_DOCUMENT_DELETED` hint. It resolves `get_tenant_one_id()` (an `await`) *before* entering the worker thread, builds the `ApiAuthContext`, `await run_in_threadpool(_delete_owned_document, doc_id, api_ctx)`, and answers `Response(status_code=204)` — or 404 when the worker reports a lookup miss.
- **Reaching `_delete_document`: a deferred import, not an extraction.** `server/main.py` imports `server.documents_api` at load to mount the router, so a module-level `import server.main` here would be circular (`documents_api` already keeps a local `get_conn` for exactly this reason). The import is therefore **function-level**, inside the worker: at request time `main` is fully loaded, the import is a dict hit, and — decisively — there is still exactly **one** `WRITE_LOCK` object in the process. New module-level imports are only `starlette.concurrency.run_in_threadpool` and `server.api_auth.{ApiAuthContext, get_tenant_one_id}` (`api_auth` imports neither `main` nor this module, so no cycle).
- **`_delete_owned_document(doc_id, api_ctx) -> bool` runs entirely off the event loop.** The helper is synchronous, takes the process-wide `threading` `WRITE_LOCK`, and for a public-root caller shells out to git (a commit, and seconds of network when `KB_GIT_PUSH` is on) — blocking the loop on that would stall every other request. Two consequences: it opens and closes **its own** SQLite connection inside the worker (SQLite forbids using a connection across threads, and this module's `get_conn` deliberately opens on the event-loop thread), and it must **not** wrap its lookup+call in `with WRITE_LOCK:` — `threading.Lock` is not reentrant and the helper takes the lock itself, so wrapping would self-deadlock. It mirrors the `/api` handlers exactly: unlocked lookup, helper takes the lock.
- **Tenant-scoped lookup is the whole authorization.** `db.get_document(conn, doc_id, tenant_id=str(api_ctx.tenant_id))` — a miss returns `False` ⇒ 404, so another tenant's id is an ordinary 404 (never 403) and the delete can never cross tenants. This route deliberately does **not** reuse P19's `_resolve_readable_doc` public fallback: reading a public document must not imply deleting it.
- **The `is_public` bridge must carry a `UUID`.** `ApiAuthContext.tenant_id` is typed `UUID | None` and `get_tenant_one_id()` returns a `UUID`, so `is_public = ctx.tenant.id == tenant_one_id` only compares equal when the tenant id is passed **unstringified**. A `str(...)` there would make `is_public` permanently `False` and a tenant-#1 member's delete would silently take the non-public branch — wrong content root (`tenants/<uuid>/` instead of `docs/`), no Recent-index update, no git commit. `_tenant_root`/`_tenant_filter` `str()` the value themselves, so the UUID is the right thing to hold. (`resolve_api_write`'s `tenant_id is None` legacy branch is dropped here: the `/app` plane only exists when the accounts plane is configured.) The public branch was exercised live at the P21 review — a tenant-#1 delete unlinks from `docs/` and leaves `tenants/<uuid>/` alone.
- **Inherited semantics, stated so nobody re-derives them.** Same helper ⇒ same non-transactional ordering (file unlink first; a failed commit reports `committed:false` and never restores it), same hard/no-undo delete, and **not idempotent** — a repeat delete answers 404. A git commit/push failure is swallowed into the helper's discarded result dict, so the route still answers 204.

### Document version history (P23, new)

P23 turns a re-publish into a **new version of the same document** instead of a 409 or a destructive overwrite. The load-bearing constraint is that **the content DB is disposable** — reindex rebuilds it from files and `init_db` drops/recreates the content tables on a pre-tenancy DB — so history lives **on disk** and the DB tables are derived (see **data**/**decisions**).

- **`documents.py` — archive primitives + a byte-preserving serializer.** `ARCHIVE_DIR = ".versions"` (the one constant `reindex` imports; `graph_hook`/`site_smoke` carry the literal because they must never import `server/*`); `archive_dir_rel_path(rel)` / `archive_rel_path(rel, version)` / `parse_archive_rel_path(arch_rel)` — the path ↔ `(rel_path, version)` bijection (zero-padded `v0001.<ext>`, extension mirroring the document's); `set_frontmatter_version(text, version)` — edits the `version:` line **in place** inside either frontmatter flavor and touches nothing else, so an archived file is a faithful copy rather than a re-serialization (unknown frontmatter fields and the exact body survive); `read_document_version(root, rel)` (the drift path — `None` when there is no file, `1` when there is no `version:` line); `archive_document_file(...)` (copy-before-replace; returns the archive rel_path, or `None` when there is no file to keep, and re-archiving the same version is idempotent by construction); `remove_archive_dir(...)` (delete path; `rmdir`-prunes the now-empty `<project>/` and `.versions/` parents, never recursively). `serialize_frontmatter` / `serialize_html_frontmatter` / `write_document_file` gained an optional `version`, emitted **after `date:` and only for version ≥ 2** — which is what makes "no `version:` ⇒ v1" a real no-migration story.
- **`db.py` — schema + CRUD.** `documents.version INTEGER NOT NULL DEFAULT 1` in `_SCHEMA` **and** in `init_db`'s idempotent `ALTER TABLE … ADD COLUMN` ladder; the `document_versions` table keyed `UNIQUE(tenant_id, rel_path, version)` (identity-keyed, **not** FK'd to `documents` — see **data** for why). New helpers: `upsert_document(..., version=1)`, `upsert_document_version(...)` (idempotent, so reindex re-upserts without clearing), `list_document_versions(conn, rel_path, tenant_id=…)` (version DESC, carries both bodies), `get_document_version(...)`, `delete_document_versions_by_path(...)`, and `find_latest_document_by_slug(...)`.
- **Target resolution (`main._resolve_version_target`).** `new_version: true` resolves the document to supersede, always tenant-scoped: an explicit **`rel_path`** names it directly; otherwise the **newest `(project, slug)`** wins — `ORDER BY date DESC, id DESC LIMIT 1`, i.e. exactly `list_documents`' newest-first ordering, so "newest" means the same thing everywhere in the store. **A miss is not an error**: it falls through to a plain v1 create at the request's own computed `rel_path`, so an agent that guessed wrong still publishes instead of 404ing. Caveat: `slug` defaults to `slugify(title)`, so a **retitled** v2 must pass `slug` or `rel_path` explicitly or it resolves to nothing and creates a new document.
- **Identity is immutable across a version chain → two 422s.** A resolved target whose `format` differs from the request's, or whose `project` differs, is a **422** ("publish it as a new document instead"), never a silent coercion — the `rel_path` encodes both the project dir and the extension, and the archive dir sits beside it. Only an explicit `rel_path` can reach either guard. Conversely a resolved target's `date`/`slug` **win over the request's**, and the response echoes the target's.
- **Archive-then-write, inside the one `WRITE_LOCK` (F10).** Order in the critical section: archive the current body → write the new body at the **same** `rel_path` with `version: N+1` → Recent index → DB upsert (`created_at` preserved by the existing `ON CONFLICT`, `updated_at` refreshed) → scoped git commit staging the archive file as a **third path**. The `document_versions` row is inserted from the superseded **DB row**; when there is a file but no row (drift, the overwrite path), the file is archived anyway — numbered from its own `version:` frontmatter — and the next reindex derives the row from the archived file, because disk is canonical.
- **`overwrite: true` now archives instead of destroying, and shares the version chain** (it archives v`N` and publishes v`N+1`). Status and every existing response key are unchanged; `version`, `previous_version`, `archived_path` are additive. This is the phase's one behavior change to an existing contract, and it is a strict improvement: the legacy destructive path stops losing data.
- **The 409 path keeps its status and every existing key**; its `detail` gains `version` + a `hint` naming the versioned retry **only when an existing DB row was found** (a disk-only conflict is not versionable). The CLI's 409 explainer is unaffected.
- **Delete removes the archive.** `_delete_document` deletes the whole `.versions/<project>/<date>-<slug>/` dir + rows and stages the removal in the same scoped commit; the `/api` response gains `versions_removed` (the `/app` route still answers 204). Leaving readable bodies of a "deleted" document on disk — and in the public git tree — would be a retention wart, and reindex would keep resurrecting the rows.
- **`reindex.py`.** `.versions` joins `RESERVED_DIRS` (and `server/seed.py` imports that constant, so the archive dir is also kept out of project discovery — otherwise `.versions` would be provisioned as a *project* in the accounts registry); `_index_file` derives `documents.version` from frontmatter (absent/garbage ⇒ 1); `_walk_versions` + `_index_version_file` rebuild `document_versions` per content root and drop rows whose archive file vanished. The report gains additive `versions_indexed` / `versions_removed`.
- **Read routes — five, all additive, all unmetered (F4), no write path touched.** Shared envelope on both planes: `{rel_path, current_version, total, versions[]}`, `versions` = **superseded bodies only**, newest first; an **unversioned document answers `current_version: 1, total: 0, versions: []`, never a 404**. `/api` (`resolve_api_read` + `_tenant_filter`): `GET /api/documents/by-path/{rel_path}/versions` and `.../versions/{version}` — declared **before** the bare by-path route, because `{rel_path:path}` is greedy and Starlette matches in declaration order (any future by-path suffix route must go above it too). `/app` (`optional_user` → `_resolve_readable_doc`, member **or** public-project anonymous, every miss a 404 never a 403): `GET /app/documents/{id}/versions`, `.../versions/{version}`, and `.../versions/{version}/raw` (archived HTML with the P16 sandbox headers repeated verbatim). Because `document_versions` is identity-keyed, each id-keyed route resolves the document row **first**, then reads the archive by that document's `rel_path` scoped to the **owning** document's `tenant_id` (not the caller's) — which is what lets a public document's history be read anonymously without ever crossing tenants. **The current version is deliberately not addressable as a version** (a 404 on both planes); the current body is the document read.

### After-response publish worker (P24, new)

P24 fixes a client-visible bug with no new dependency and no contract removal: `POST /api/documents` used to run **two unbounded network stages between the durable save and the 201** — `gitops.push` (fetch + rebase + push, two SSH round-trips, and until P24 `subprocess.run` with **no `timeout=` at all**) *inside* `WRITE_LOCK`, and the Gemini embed just after it. Both spend the caller's deadline on work whose result never appears in the response, so a client posting with `curl --max-time 5` saw a transport failure for a document that was already written, committed and live. The confirmed refinement of the original hypothesis: the culprit was never "git commit" (local, tens of ms) but the *network* stages.

- **`publish.py` — one process-wide FIFO daemon worker + queue**, started lazily on the first `submit`. `submit(name, task)` only appends to a `queue.Queue` (it never raises, and is the only work done on the request thread); `_loop` runs tasks in submission order, catching `BaseException` so the worker can never die; `pending()`/`drain(timeout=30)`/`last_error()`/`reset_last_error()` are the test + shutdown surface. `drain()` is the **only** synchronization point and must never be called from a request path — a queued push takes `WRITE_LOCK`.
- **Why a queue rather than Starlette `BackgroundTasks`.** Both run after the handler, but with the `BaseHTTPMiddleware` usage-metering in the stack the ordering guarantee is subtle; a queue makes "the response never waits" a **property of the code** (`submit` is a `put`, the work runs on the `kb-publish` thread), which is exactly the trap that would otherwise reproduce the bug being fixed. Regression-tested by blocking `gitops.push` on an `Event` and asserting the 201 returns in under a second.
- **The worker re-takes `WRITE_LOCK`** (in the task body in `main.py`) because a rebase mutates the work tree and must not race a write's file write. `WRITE_LOCK` is **not reentrant**, so tasks are always **submitted outside it** — both submit sites (`create_document`, `_delete_document`) sit after the critical section. Pushes stay **serialized** by the single worker: never two concurrent rebases, one push per write in submit order (coalescing is a possible optimization, deliberately not needed for correctness).
- **Failures never reach the caller** — the response is long gone. A task's exception is logged to stdout as `[kb-api] publish: <name> FAILED: <err>` (the container log is the operator's surface, see **operations**) and kept in `last_error()` for tests. **There is no success log line**, which is why the box's positive assertion is git state, not a grep. The write itself is already durable and a failed push republishes on the next successful one.
- **Bounded git is what makes the lock-holding worker safe.** Without `KB_GIT_TIMEOUT_S` a hanging SSH connection would hold `WRITE_LOCK` indefinitely and block *every subsequent write in the process* — worse than the bug being fixed. With it, the subprocess is killed, the task raises `GitError`, the lock is released, and the doc publishes on the next push.
- **Accepted, recorded scope limits.** The queue is **in-memory**: a crash before it drains loses the *push*, never the save, and the next successful push publishes everything accumulated (the app's shutdown hook drains). The worker-side Gemini embed has **no client timeout** — it can no longer delay a response, but a stalled embed blocks the single FIFO worker and therefore every push queued behind it until restart (availability of the off-box backup, not correctness; a deferred job). The queue is unbounded. The metering middleware's Postgres write still happens between the handler returning and the body reaching the client (local container, ms).

## Invariants

- **Single-writer**: the write lock is **in-process**, so the API must run **one uvicorn worker** — never scale workers. **(P10)** the async Postgres accounts plane sits alongside but never touches `WRITE_LOCK`; the single-worker invariant is unchanged. **(P21)** the `/app` delete route also holds it, via the same `_delete_document` helper reached through a deferred import — **exactly one `WRITE_LOCK` object exists**, defined only in `server/main.py`; a route that reaches it must never take it a second time (the lock is non-reentrant). **(P24)** the publish worker takes that same one lock from a *background* thread, so a publish task must always be **submitted from outside the critical section** — submitting while holding it would self-deadlock the moment the worker ran.
- **(P24) No network I/O before a write's response.** Everything between the request and the 201 is local (validate → archive → file write → Recent/landing → DB commit → local `git add`/`commit`); anything that talks to GitHub or Gemini goes on the publish worker. A new pre-response network call would silently re-introduce the client-timeout bug this phase fixed. Corollary: **every git subprocess is bounded** by `KB_GIT_TIMEOUT_S`, because the worker holds `WRITE_LOCK` while it pushes.
- **(P10) Dormant control plane / legacy parity**: with `DATABASE_URL` unset the accounts engine is never created and `/api/*` is byte-for-byte the pre-P10 single-`KB_API_TOKEN` deployment (the 65-test legacy regression gates this).
- **(P11) Metering is best-effort and never fails a request**: the sync handlers only *stash* a hint; the async middleware records post-response, on a 2xx with a hint and `tenant_id` set, and `record_usage` swallows every error (logged, never raised). In legacy mode the hint carries `tenant_id=None`, the guard skips, and no engine is created — so metering is fully inert and the frozen `/api/*` contract is unchanged (same 65-test legacy regression). The open read/list path stays **unmetered** (no `request.state.usage` stash) so it holds no hot-path write.
- **(P10) Tenant identity lives in the file path**: `reindex` re-derives `tenant_id` from the content root (`docs/` → tenant #1; `tenants/<uuid>/` → the dir name), so cross-tenant isolation survives a full disposable-DB rebuild. WAL still gives read concurrency. **(P24)** the process now runs **exactly one** background worker — the `kb-publish` daemon thread, for post-response publish/embed work only. It is still one uvicorn worker holding one `WRITE_LOCK`; nothing else may be moved onto a thread that mutates the tree.
- **`docs/`-canonical, never-rollback**: a failed git commit leaves the file/DB written (`committed:false`); `docs/` stays canonical and reindex reconciles. Both the POST write path and the P4 DELETE path share this contract. Git stages only the touched paths and never force-pushes. **(P24)** the same holds one step further out: a failed *push* leaves the local commit intact and is invisible to the caller (it is logged), so `docs/` on the box is canonical even when `origin/main` is behind.
- **(P23) History lives on disk; the version tables are derived**: `documents.version` comes from the current file's frontmatter and every `document_versions` row from an archived file, so a full DB wipe + reindex reproduces the whole history. A version-history feature that stored bodies **only** in SQLite would be silently erased by the next boot reindex — never build one. Archived bodies are never inserted into `documents_fts`, never embedded and never graphed, so search/graph output for an unversioned corpus is unchanged.
- **DB/file consistency**: a POST-written document and a later reindex produce identical stored `markdown` — no phantom drift. `related` and the sanitized `source_repo` round-trip identically through the write path and reindex.
- **Embeddings are a disposable cache, best-effort everywhere**: no Gemini key → skipped; an API/429 failure → per-doc skip, reported and retried next reindex — never fails a reindex, a write, or a search (which degrades to BM25-only). **(P24)** the write-path embed runs on the publish worker rather than in-request, so it cannot affect a write's latency either; it opens its own SQLite connection there (a connection is not shareable across threads) and fails closed, with the next reindex catching up.

## Error Handling

- `ConventionError`/`FrontmatterError` (incl. `validate_related` shape) → 422; an invalid `reindex_path` rel_path → 422; **(P23)** a `new_version` write whose resolved target has a different `format` or `project` → 422; existing target → 409 (names the doc, and since P23 hints at the versioned retry when a DB row backs it); a missing delete target → 404; FTS5 raw-syntax error → 400 (`SearchQueryError`); git failure → 201/200 with `committed:false` + `commit_error`.
