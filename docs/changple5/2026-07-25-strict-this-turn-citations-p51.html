The Answer That Cited Nothing

How changple5 made its chat citations strictly this-turn — a walkthrough of phase P51.

An operator opened a shared conversation from production and found an answer that looked perfectly researched: four concrete project examples, specific details, confident prose. It cited nothing. No 참고 문서 card, no citation chips, and sixteen sentences ending in a strange floating period — …했습니다 .. At the very bottom sat a line the user was never supposed to see, listing internal document IDs.

This document explains what was actually broken, why nothing caught it, and how the fix turned an aspirational rule into an enforceable one.

Background

What kind of system is this?

changple5 runs a Korean startup-advice chatbot. It is a RAG system — retrieval-augmented generation. Rather than letting the language model answer from whatever it absorbed during training, the system first searches a curated corpus (a library of 창플 café posts written by real practitioners), hands the model the documents it found, and asks it to answer from those documents. The retrieved documents are the only permitted evidence.

Why RAG at all?

A raw language model will happily invent plausible-sounding business advice. RAG constrains it to a corpus the operator trusts, and — crucially — makes the answer checkable: each claim can point at the document it came from. That pointing is called attribution, and the visible result is a citation.

How a citation physically travels through this system

Citations here are a small pipeline with four stations:

Station 3 has one rule, and it is strict: a marker is only rendered if that post_id is in this turn's retrieved-documents map. An unknown id is silently deleted. That rule is deliberate — it is what stops the model "citing" a document it never actually looked at this time.

The four symptoms the operator found

#SymptomWhat the user saw
1 Citation collapse A long, plainly document-grounded answer stored with cited_documents: []. No chips, no 참고 문서 card.
2 Orphan whitespace Sixteen occurrences of …했습니다 . — a space marooned where a deleted marker used to be.
3 Internal annotation leak The answer ended with (이 턴에서 인용한 문서: post:56007="…", post:51200="…") — an internal, model-only note, printed to the user.
4 Korean bold broken **"싸게 만든 공간"이 아니라…**을 rendered as literal asterisks instead of bold text.

Plus two product asks from the operator: make the model actually use its multi-search budget so answers go deeper, and raise the default reasoning effort.

The scary part

Symptom 1 is not "the app crashed". It is an ungrounded answer that looks grounded — the single worst failure mode a RAG product has, because the user has no signal that anything went wrong. And the system had two safety gates built specifically to catch ungrounded answers. Neither of them fired.

Intuition

Two sets that were allowed to differ

Everything in this phase follows from one observation. There are two sets of documents in play on any given turn:

Set A was always computed strictly per turn. Set B was not. So the model could look at a document from three turns ago, write a sentence grounded in it, cite it honestly — and have that citation silently deleted, because rendering only recognizes Set A.

Now consider what happens as more and more of an answer rests on Set B \ Set A:

Fraction of markers that are out-of-mapResult
0%Normal answer with chips. Healthy.
SomeAnswer keeps some chips; the deleted ones leave …했습니다 . behind. Cosmetically odd, quietly lossy.
100%The collapse. Zero citations survive. The answer persists looking authoritative and sourceless.

Why the existing safety gates were blind

The system had two grounding backstops. Each one checks a different condition, and the collapse slips exactly between them:

GateFires whenOn the collapsed turn
_should_use_no_document_default_chat_response Retrieval ran but the document map is empty ❌ The map was not empty — search had returned documents
_should_use_ungrounded_memory_fallback Zero retrieval calls and no citations ❌ Retrieval calls were not zero

The shape of the hole

"Retrieved something, and then cited only things it wasn't given." Both gates ask about the inputs of the turn. Neither asks about the outcome: did any citation actually survive rendering? That third question is the fix.

Two fixes, not one

A tempting shortcut is to relax the rule: "if the model cites something from an earlier turn, just allow it." The operator rejected that, and the reasoning is worth internalizing. A document the model saw three turns ago is in its context as text, but the system no longer has it as a record — the title, the URL, the freshness. Allowing citation from memory means citing something nobody re-checked. The ruling was:

Citations are strictly this-turn. If the user asks about something from many turns back, the agent must retrieve it again.

Which forces two independent pieces of work, because there are two independent failures:

  • Supply. Stop out-of-map documents reaching the model at all. If Set B can never exceed Set A, the model is never tempted.
  • Detection. Notice when it happens anyway. Because the next supply route hasn't been invented yet, and silence is what made this defect survive in production.

Fixing only supply leaves the pipeline unable to notice the next leak. Fixing only detection leaves the model permanently tempted. So the phase did both.

A completely separate bug: Korean bold

Symptom 4 has nothing to do with any of the above — it is a markdown-parsing bug, and a beautiful one. Markdown's CommonMark specification decides whether ** can close a bold run using a rule about the characters immediately around it, called flanking. Simplified: a closing ** preceded by punctuation must be followed by whitespace or more punctuation.

InputRenders asWhy
**밥도뚝**은 합성어밥도뚝은 ✅ Closer preceded by a letter — fine
**…잘 남는 공간"**을**…**을 ❌ Closer preceded by ", followed by the particle 을
**…(매일 먹는 식사)**에**…**에 ❌ Closer preceded by ), followed by 에

English rarely hits this: we put a space or a period after a bold phrase. Korean hits it constantly, because particles (은/는/을/를/에…) attach directly to the word with no space. A quoted or parenthesized phrase followed by a particle is completely ordinary Korean — and completely unrenderable under the rule as written.

The property that makes the repair safe

When CommonMark refuses to close a run, it does not half-parse it. The entire **…**을 stretch survives as one literal text node in the parsed tree. So after parsing, any **…** still sitting inside a plain text node is by definition a run the parser rejected. That is a precise signal, not a guess — which is why the repair can be a small post-parse pass instead of a rewrite of the parser.

Code

The work landed as five slices. We'll walk them in dependency order, since each builds on the last.

Slice 1 — detection: a third gate, and telemetry

First, rendering had to report what it dropped. The renderer already knew — it just logged it at debug level, which production does not keep. An optional collector list was threaded through:

def render_citation_markers(
    text: str,
    *,
    valid_post_ids: set[int] | None = None,
    filtered_post_ids: list[int] | None = None,   # <- new, optional
) -> tuple[str, tuple[int, ...]]:

Optional by design: the consulting and content-draft features call this same function, and neither needed a single edit. Then the new gate, sitting beside its two siblings:

def _should_use_filtered_citation_fallback(completion) -> bool:
    if completion.security_locked:
        return False
    if completion.cited_document_post_ids:   # something survived — fine
        return False
    return bool(completion.filtered_citation_post_ids)   # ...but we dropped some

Read it as a sentence: at least one marker was filtered, and zero citations survived, and this isn't a security refusal. When it fires, the answer is replaced with the same fixed grounded refusal the other two gates use, and the conversation checkpoint is reset.

Two design decisions worth noticing

No length bar. The sibling ungrounded gate only fires on answers over 400 characters, so short greetings pass. This gate has no such threshold: an answer citing ids it was never given is ungrounded at any length.

It replaces text the user already watched stream. Grounded turns stream token-by-token, so by the time the gate decides, the user has read the answer. The final SSE frame carries the refusal and the web client prefers it, so the text is swapped out. Ugly — and deliberately accepted, because persisting an ungrounded answer is worse.

The orphan …했습니다 . needed fixing in three places, which is the interesting part. Deleting a marker must also delete the space that introduced it, and that space lives in a different place depending on the path:

PathFix
Final renderWhen a whole marker group renders to "", consume the preceding run of spaces/tabs — never a newline, which would join two lines
Live streamThe parser now holds a trailing whitespace run in its own buffer, because the space and the marker usually arrive in different network chunks
Wholesale stripA second regex, [ \t]* + the marker pattern, for surfaces that must carry no citations at all

The streaming case is the one that would have been missed. A test that only checks the stored text passes happily while the live stream still shows the artifact.

Slice 1 also hardened the checkpoint rebuild. This is subtle: state is written through LangGraph reducers, and the message reducer appends rather than replaces, while the document-map reducer merges rather than clears. So the old "rebuild" was only correct because a delete ran immediately before it. Now the payload resets through the reducers themselves:

"messages": [RemoveMessage(id=REMOVE_ALL_MESSAGES), *rebuilt_history],
"retrieval_call_count": RETRIEVAL_CALL_COUNT_RESET,
"retrieved_documents_by_post_id": {RETRIEVED_DOCUMENTS_RESET_KEY: {}},

Verified against the real state class with the delete deliberately skipped: the old payload left the previous turn's documents intact; the new one produces exactly the rebuilt history.

Slice 2 — supply: three routes, all closed

Root-causing found three distinct ways an out-of-map document could reach the model.

Route 1 — thread reuse. The system cached the model's conversation thread and reused it whenever a predicted fingerprint of the conversation history matched what was stored. A reused thread keeps every prior turn's ToolMessage — which is to say, the full text of every document retrieved in every earlier turn, complete with ids and titles. Set B, unbounded.

The fix is structural rather than surgical. The thread is now always torn down and rebuilt from the backend's own record of the conversation, and the rebuilder emits only human and assistant messages:

def _build_chat_agent_history_messages(messages) -> list[AnyMessage]:
    history_messages: list[AnyMessage] = []
    for message in messages:
        content = _format_message_context(message)
        if message.role == "user":
            history_messages.append(HumanMessage(content=content))
            continue
        history_messages.append(AIMessage(content=content))
    return history_messages

Look at what that function cannot produce: a ToolMessage. No tool message means no document body, no id, no title from any earlier turn. The policy is now true by construction, and a test asserts exactly that property.

Why not just delete the tool messages?

Because a tool result is paired with the assistant message that requested it. Remove one without the other and you hand the provider an invalid message list. Rebuilding from scratch sidesteps the pairing problem entirely — a good example of "change the shape so the hazard cannot exist" beating "handle the hazard carefully".

Route 2 — the annotation. Prior assistant turns carried a note listing what they had cited, in exactly the form the user later saw leak:

-  (이 턴에서 인용한 문서: post:56007="…", post:51200="…")
+  (이전 턴 참고 자료, 인용 불가: 창플 카페 "…", 창플 카페 "…")

Title and source name only — no id. And the system prompt used to quote that exact format to the model, which is very likely how the model learned to reproduce it. The rewritten prompt describes the property in words; a test asserts the literal old string appears nowhere in the prompt.

Route 3 — contradictory tool guidance. Every successful search result shipped a line of instruction with it, and that line said the opposite of the prompt:

- Only cite post_ids returned in this or earlier successful tool results
+ Only cite post_ids returned by a successful tool result in THIS turn;
+ a post_id from an earlier turn is not citable unless this turn's search
+ returns it again.

A rule the system contradicts elsewhere in the same context window is not a rule. Finally, because a model can reproduce a shape from training even after you remove it from context, a defensive stripper removes the annotation from persisted answers — anchored on its label, confined to one line, and tolerant of at most one level of nesting so that ordinary Korean parentheses like 백반(매일 먹는 식사)에 survive untouched.

Slice 3 — the Korean bold repair

A small remark plugin, wired as the first entry in the plugin chain. It walks only text nodes (so code spans are excluded structurally, not by a rule somebody might forget) and rewrites a run only when it matches the exact failure signature:

  1. the delimiter is ** or * and nothing inside is *;
  2. the last enclosed character is Unicode punctuation — the reason the closer was refused;
  3. the character after the closer exists and is neither whitespace nor punctuation — the particle;
  4. the opener is legitimate: string start, whitespace, or punctuation before it.

Ordering is load-bearing and test-guarded: the citation plugin recurses into non-text children, so a citation chip inside a repaired bold span still works — but only while the repair runs first.

The trap that the four conditions do not catch

Markdown text values arrive at the plugin already unescaped. So a user writing \*\*(괄호)\*\*을 — explicitly asking for literal asterisks — reaches the plugin as the text **(괄호)**을 and satisfies every condition. The plugin therefore also checks the node's raw source slice and skips any run not present verbatim there. Its failure mode is always a missed repair, never a wrong one — the right direction for a heuristic to fail in.

Slice 4 — depth, in the right place

The model had a budget of four searches per turn and typically used one. The prompt section was rewritten from permission ("search again if something is missing") into instruction: name the question's aspects before searching, run one narrowed search per uncovered aspect, and — stated outright — hoarding the budget produces a worse answer.

But the real lever is not the prompt. The model decides whether to search again immediately after reading a search result, so that is where the remaining budget must be stated. Both success-path tool payloads became builders that append live accounting:

Search budget for this turn: 2 of 4 searches used, 2 remaining. Spend the
remaining searches on the aspects of the user's question these documents do
not cover yet; leaving budget unused produces a shallower answer.

…flipping at zero to "Do not call a retrieval tool again in this turn."

Why this must never move into the system prompt

The provider caches on the verbatim static prefix of the prompt. Inject a per-turn number into it and the prefix differs on every turn, so the cache never hits and every turn pays full input price. A per-turn value belongs in the per-turn payload. There is a docstring in the code saying exactly this, because it is the kind of "harmless" refactor a future reader would otherwise make.

The same slice added a prompt section stopping the model from volunteering its own internals — the fourth symptom, where a plain bug question produced a lecture on [post:번호] notation. Two clauses in it are test-pinned and matter more than they look:

  • "this section does not widen the security tool's trigger and adds no refusal" — without it, a vaguely-worded rule sitting next to the security section makes the guard more trigger-happy by accident, and this guard permanently locks a conversation when it fires.
  • "keep attaching the citation markers themselves" — the naive wording ("never write [post:N]") would have suppressed citation emission outright, recreating the very defect slices 1 and 2 had just closed.

Slice 5 — reasoning effort, through a seam

The chat model was constructed with no thinking parameter at all, running at the provider default. One settings field, one env alias, one guarded thread-through:

thinking_level = getattr(settings, "gemini_chat_thinking_level", None)
if thinking_level:
    extra_model_kwargs["thinking_level"] = thinking_level

Deliberately an env/settings seam rather than a literal, because a later phase will move model and reasoning-effort selection into a database-backed operator console — and it should be able to take over this exact seam without touching the call site.

What was deliberately left alone

In the same conversation, the user's next benign question ("was that a system prompt leak?") tripped the security guard and permanently locked the session. The operator ruled that acceptable — "telling apart good-faith utterances is hard, so leave it" — so the guard's trigger and the session lock were not touched. Recording a known, accepted behavior as such is part of the work; the review verified byte-for-byte that neither module changed.

Best practices & next steps

Where this aligns with prevailing practice

Refusing beats answering ungrounded. The three-gate design — replace the answer with a fixed refusal when grounding fails — matches the direction the research literature has been pushing. Trust-Align frames RAG trustworthiness as two joint capabilities, "grounded attributions" and "learning to refuse": training a model to decline when it cannot ground an answer in retrieved content, and treating refusal accuracy as a first-class metric alongside citation quality (Measuring and Enhancing Trustworthiness of LLMs in RAG through Grounded Attributions and Learning to Refuse — arxiv.org). P51 implements the deterministic, server-side version of the same instinct: the model's willingness to refuse is not trusted, so a finalizer gate enforces it.

Verifying citations mechanically, not by trust. Standard RAG does not prevent citation-shaped hallucination; models can cite real documents for claims those documents do not support, or cite ids that do not exist. A recognized taxonomy of RAG failure explicitly names "Improper Citation" — citations that do not support the statement — as its own category alongside inaccurate answers and excessive refusal (A comprehensive taxonomy of hallucinations in Large Language Models — arxiv.org). Enforcing citation validity with set membership against this turn's retrieval, rather than trusting model output, is the mechanical-verification pattern this literature recommends.

The Korean bold bug is a known, unresolved spec-level defect — not a local mistake. The CommonMark issue tracker has carried this since 2020: emphasis fails inconsistently when delimiters meet CJK punctuation, because "in Japanese, as a general rule there are no spaces in sentences", and the issue remains open with no assigned resolution (commonmark-spec issue 650 — github.com). A detailed Korean-language analysis explains the mechanism precisely — the closing ** in **마크다운(Markdown)**은 is preceded by punctuation and followed by a letter, so it fails the right-flanking test — and notes that the "markdown-cjk-friendly" project has already been adopted by GitLab's markdown flavor (유루메's writeup on CommonMark and CJK emphasis — hackers.pub). Patching this at the plugin layer is the same remedy the wider ecosystem has converged on.

Where this deliberately diverges

A narrow signature-gated repair instead of adopting a general CJK-friendly parser. The ecosystem fix (remark-cjk-friendly / GLFM) changes the flanking rules wholesale. P51 instead repairs only runs matching an exact four-condition signature, plus a raw-source check. That is strictly less capable — triple runs and runs split across nodes stay literal — but the renderer is the app's only markdown mount, shared by chat, the share view, consulting reports, and the operator workspace, so a regression would land on every surface simultaneously. Choosing the narrower, auditable repair over the more complete one is a defensible call for a shared renderer; it is worth revisiting if the unrepaired cases show up in real answers.

Refusal replaces text the user already read. Most systems that gate on grounding do so before streaming. Here, grounded turns stream immediately for latency, so the gate can only act at the end — swapping out an answer mid-read. That is a real UX cost, accepted knowingly rather than accidentally.

Next steps

  1. Watch the two warning logs before assuming the job is done. "Filtered N out-of-map citation post_ids" should now be rare. If it stays frequent in production, a supply route is still open — and that log is the instrument that would identify it. Sustained volume is a finding, not noise.
  2. Measure the cost delta. The phase pushes in both directions: deeper multi-search and higher reasoning effort cost more, while dropping prior-turn document bodies from context costs less. The static prompt prefix grew about 30%. The net per-turn change is currently unknown, and against a codebase that ran an explicit cost-reduction phase earlier, "unmeasured" should not stay the answer for long.
  3. Consider claim-level verification as the next tier. Set-membership checks whether a cited document was retrieved; it does not check whether the document actually supports the sentence. Decomposing an answer into atomic claims and checking each against its cited chunk is the recognized next tier of rigor (Building Trustworthy RAG Systems with In-Text Citations — haruiz.github.io).
  4. Give the other citation surfaces the same visibility. The filtered-id collector is opt-in, and consulting and content-drafts currently pass nothing. They are subject to the same class of failure; enabling it there is a one-line change per call site.

Quiz

1. The two pre-existing grounding gates both failed to catch the collapsed answer. Why?

Both gates ask about the turn's inputs. The collapsed turn had healthy-looking inputs — it retrieved documents successfully — and failed on the outcome: no citation survived rendering. That third question is what the new gate adds.

2. Why does rebuilding the model's thread from the backend's conversation record eliminate the prior-turn document leak "by construction"?

The document bodies travel inside ToolMessages. The rebuild function's return type can only contain HumanMessage and AIMessage, so no filtering step is needed — the unwanted content cannot be constructed in the first place.

3. The orphan …했습니다 . had to be fixed on the streaming path separately from the final render. What makes the streaming case different?

The parser now holds a trailing whitespace run in its own buffer, separate from the partial-marker buffer, so a marker arriving in the next chunk can still consume the space that introduced it. A test asserting only on stored text would pass while users still saw the artifact.

4. Why does the per-turn search-budget message ("2 of 4 searches used…") live in the tool result rather than in the system prompt?

Prefix stability is cache-load-bearing. It also happens to be the right place editorially — the model decides whether to search again immediately after reading a search result, which is exactly where the remaining budget matters.

5. The Korean-bold plugin checks the node's raw source slice in addition to its four signature conditions. What would break without that check?

By the time the plugin sees the text, \*\* has become ** — satisfying every one of the four conditions. Comparing against the original source characters is what tells the difference. Code spans, by contrast, are excluded structurally: they are their own node type, and the plugin only walks text nodes.
