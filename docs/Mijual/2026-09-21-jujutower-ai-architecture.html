1. Background — a domain that punishes a confident guess

주주의관제탑 ("the shareholders' control tower") watches Korean corporate disclosure for shareholder rights that carry a deadline, and tells an individual investor what is happening to their shares, when it expires, and where in the original filing that statement came from. Everything it says is derived from public filings on DART, the Financial Supervisory Service's electronic disclosure system. There is no price feed and no market-data vendor anywhere in the system.

Three rights types ship in the MVP. It is worth knowing what each one actually is, because the AI design is a direct response to their shape.

TypeWhat it isWhat expiresReading cost
① 유상증자 신주인수권 In a 주주배정 rights offering, every existing shareholder is issued a 신주인수권증서 — a tradable certificate giving them the right to subscribe to new shares below market price. The 증서 lapses to ₩0 if it is neither exercised nor sold. The on-exchange trading window is typically five trading days. Mixed — the only type that needs the model at all
② 전환사채 오버행 A convertible bond's conversion terms — conversion price, refixing floor, when conversion requests open, when a lockup releases. Nothing expires for the shareholder; the dilution arrives on a date the filing already announced. Zero LLM — entirely structured API fields
③ 주식매수청구권 Around a merger, a dissenting shareholder can require the company to buy their shares at a set price — a floor under the stock. A two-step procedure: written dissent before the shareholder meeting, then the claim itself. Miss step one and step two does not exist for you. Zero LLM — entirely structured API fields

The founding argument of the project is that this is not an information-scarcity problem. Every one of those facts is published, by law, on DART. The gap is between 공개 (disclosure) and 전달 (delivery): hundreds of filings land per day, the answer a person actually needs ("I hold 500 shares — how much do I pay by when, for how many shares, and what do I lose if I don't?") appears nowhere in the statutory form, and the action window is short and irregular.

14.02%of allotted 증서 (51.25M of 365.53M) neither subscribed nor sold
488exposable events on the live board — 50 ① / 422 ② / 16 ③

Why this domain is unusually hostile to a language model

Plenty of products let an LLM read documents and summarise them. Four properties of this one make that posture unavailable.

  1. The output is an instruction to act, denominated in the reader's own money. Not "here is a summary of the filing" but "you hold 500 shares, you have ₩1,000,000 of value here, and the window closes on the 18th."
  2. Failure is silent and unrecoverable. A lapsed 증서 cannot be reclaimed afterwards. Korea's central securities depository runs a long-standing campaign to return unclaimed shares and dividends — cumulative returns have passed 1조원 — but that campaign can only return things that still exist. A right that lapsed is simply gone, which is why the system's whole posture is prevent before the deadline rather than detect afterwards.
  3. The source is a legal form, not prose. The value you need is scattered across numbered sections, sometimes genuinely absent, and sometimes superseded — a 정정공시 (amended filing) can move a payment date by a month, which moves the reader's D-day by a month.
  4. Every won figure is derived, not quoted. With no price feed, the theoretical value of a certificate is recovered by inverting the issuer's own pricing formula from the filing. A misread ratio does not produce a wrong sentence; it produces a wrong amount of money.
The governing constraint

AI는 '읽기'와 '말하기'를 하고, '계산'만 결정론이 한다.

The AI reads and speaks; only determinism calculates. This one sentence, taken from the project's problem brief, is the reason every design decision below looks the way it does. It is not a quality target — it is a partition of responsibilities that the code is arranged to make checkable.

2. Intuition — three layers and three inversions

The system splits the model's job in two and puts something that cannot hallucinate between them.

That much is a fairly conventional "extract then validate" shape. What makes this system worth studying are three inversions of the usual practice.

Inversion 1 — ask for the quote, never for the span

The obvious way to get a citation out of a model is to ask for one: return the value and the character offsets where you found it. That is exactly what this system refuses to do. The module that does the work says why in its first sentence:

"""Quote → citation span, **deterministically**. The model never supplies one.

This module is the reason the extractor is allowed to exist at all. §3.6's layer
2 requires a *원문 인용 스팬* per exposed value, and a span invented by a language
model is not evidence — it is a second thing to verify. So the model is asked for
one thing only, a **verbatim quote**, and this code finds that string in the
stored snapshot ...

— src/mijual/extract/locate.py, module docstring

The asymmetry is the whole point. A span is a claim; a quote is a testable claim. If a model hands you span_start=4821, you have acquired a second thing to verify and no way to verify it except by checking what is actually at 4821 — at which point you may as well have searched. If it hands you a string, you run find(). A paraphrase simply fails to locate, and the row is recorded as span-unresolved with the model's quote kept for the accuracy report.

Inversion 2 — keep the verifier's evidence out of the generator's context

This one is the most transferable idea in the codebase, and it is easy to get backwards.

A natural instinct when extraction quality is poor is to stuff more of the document into the prompt. But one of the ten fields is 청약 취급처 (where subscription is handled), and its deterministic gate is: the subscription date in the extracted value must equal the date printed at 본문 label 11, 청약예정일. If you put 본문 11 into the prompt, the model can copy the answer from it — and then the gate is no longer checking the model against the document. It is checking the prompt against itself.

Why nothing else goes in the prompt: the deterministic gate for 청약 취급처 is
"청약일 must equal 본문 11. 청약예정일", so feeding 본문 11's value into the prompt
would let the model copy the answer and the gate would be checking the prompt
against itself.

— paraphrasing src/mijual/extract/prompt.py:5-11

Generalised: an automated check is only worth its cost if its reference value was unavailable to the thing it is checking. If you are building an LLM pipeline with a validation layer, the context window and the validator's evidence set should be disjoint by construction — and that constraint should be written down next to the prompt, because the natural drift of prompt engineering is to add context until the check is vacuous.

Inversion 3 — make an invalid citation unconstructable, not filtered

The third layer, the user-facing agent, has to cite too. The usual approach is to let the model write references and then filter out the bad ones. This system instead makes bad ones impossible to express: a reference id exists only because a tool call returned it. The model cites c7 because a tool result carried c7; there is no id space in which it could invent c12 and be right. Anything marker-shaped that names nothing is simply removed from the prose.

And there are deliberately two id spaces. The model writes [[cite:c7]]; the reader sees chip 1, numbered in reading order and assigned when the answer first rests on that source. Same source, same number, without the model having to know or manage the reader's numbering.

The four verdicts, and what reaches a screen

Every extracted field ends in one of exactly four states, derived from a list of named checks rather than written by hand:

VerdictMeaningShown?
passedat least one substantive check ran and none failed yes
tbdthe filing says the schedule is suspended (추후결정) — a verified citation with null dates yes, as 추후결정 with no date at all
faileda check failed no — recorded with a reason code
not_evaluablenothing could be checked: field absent, call errored, or the gate's own reference value does not exist no — the conservative default
The rule that makes the rest work

A skipped check is not a pass. A gate all of whose checks were skipped is not_evaluable, not passed. This is the single most commonly-inverted default in validation code: "I couldn't check it, so it's fine" quietly becomes "it's fine."

A worked example, with made-up but correctly-shaped data

Take gate #1, 신주인수권증서 상장·매매기간 — the window during which the certificate can be sold on exchange. Suppose the pipeline has already collected a filing and stored its body. The extraction step sends the model one field's instruction plus a slice of that body, and gets back:

{
  "present": true,
  "value":   {"start": "2026-05-12", "end": "2026-05-18"},
  "quote":   "① 신주인수권증서의 상장·매매기간은 2026년 5월 12일부터 2026년 5월 18일까지로 하며",
  "note":    null
}

Nothing about that is trusted yet. What happens next:

  1. Locate. The quote starts with ①, which the model may well have re-rendered from the document's own marker. exact misses; trimmed drops the leading list marker and matches. The row gets a real character span, method trimmed, span_verified = false.
  2. Gate. The citation gate runs first on every field — an unlocatable quote is blocked before any arithmetic is attempted. Then the field's own named checks: the dates are in order, and the window sits between 배정기준일 and 청약일, both read from evidence the model never saw (the deterministic 본문 labels and the stored API detail row).
  3. Persist. Verdict passed, written onto the row as gate_status, so the serving layer filters exposability in SQL and never re-implements the rule.
  4. Serve. The detail page shows the window with a [근거] chip that opens the located sentence from the filing. The countdown beside it was computed by mijual.calc in KST, with no model involved at any point.

Change one thing — the model paraphrases the sentence instead of copying it — and every one of those steps still runs, but the field is recorded span_unresolved and the reader sees nothing in that slot. Not a dash, not a placeholder, not "확인 필요". Absence.

Exactly one of those six stages spends money on a model.

3.1 읽기 — the reading layer

A closed registry of ten fields

src/mijual/extract/fields.py holds the model's entire reading job as ten FieldSpec entries — warrant_trading_period, subscription_agents, forfeited_share_method, excess_subscription, issue_price_formula, refixing_terms, option_schedule, lockup_release, dissent_notice_procedure, correction_interpretation. Everything else the product displays is either a structured OpenDART API field or a deterministic 본문-label row.

That boundary is enforced, not merely intended: a test asserts the LLM registry stays disjoint from mijual.bodydoc.labels.LABEL_FIELDS. A field that turns out to be label-readable belongs in bodydoc and is not allowed to be paid for with a model call. The project's own phrasing: anything deterministically readable must not be paid for with an LLM call.

Each spec carries four things — the JSON schema of the normalized value (ISO dates, decimal ratios, enums), a per-field Korean instruction naming the 본문 location the field survey measured, the gate that will judge it (carried as documentation, so layer 1 can be read without layer 2), and an anchor regex used only to window a large document, never to parse a value.

The prompt is four rules long

규칙:
1. 아래 <본문>에 실제로 적혀 있는 내용만 사용한다. 추정·보완·외부지식·계산 금지.
   해당 항목이 문서에 없으면 present=false, value=null 로 답한다 (빈 값을 지어내지 말 것).
2. quote 는 <본문> 텍스트에서 **문자 그대로 복사**한다. 요약·교정·줄임·재배열 금지.
   길이는 20~200자 정도로, 값이 실제로 적힌 부분을 고른다.
3. 날짜는 YYYY-MM-DD, 비율은 소수(20% -> 0.2), 금액은 숫자만(원 단위)으로 정규화한다.
4. 확신이 없으면 present=false 로 두고 note 에 이유를 한 줄 적는다. 추측은 오답보다 나쁘다.

— src/mijual/extract/prompt.py:32-38

Rule 1 forbids inference, outside knowledge and calculation. Rule 2 is what makes the locator possible. Rule 4 ends with the line worth stealing: 추측은 오답보다 나쁘다 — a guess is worse than a wrong answer. Which is exactly right when a downstream gate exists: a wrong answer gets caught and recorded; a plausible guess is engineered to survive.

The audit row is the real output

Every call writes an ExtractionCall row (model, model version, schema version, prompt version, thinking level, prompt/thoughts/output token counts, ▷ estimated cost, latency, attempts, and the raw response), and every field writes an Extraction row keyed (filing_version_id, field_key, schema_version) carrying:

  • the normalized value, and a human-readable value_summary
  • the quote, plus span_start / span_end / span_status / span_verified / locate_method
  • the gate verdict: gate_status / gate_reason_code / gate_note / gate_checked_at

Note what that schema makes possible: you can ask the database "how often did the model produce a quote that is not in the document, by field, by month" without re-running anything. The accuracy measurement in §3.5 is a query over rows that already exist.

Three rules bind every one of them, and they are the transferable part:

  1. The citation gate runs first, on every field. A value whose quote could not be located is not a citation, so it is blocked before any arithmetic is attempted.
  2. A gate compares against evidence the model never saw — deterministic 본문 labels and the stored API detail row, never against another model output. (This is inversion 2, restated as an invariant rather than a prompt-authoring habit.)
  3. Conservative on absence. A check whose reference value does not exist is skipped, not passed.

When the corpus beats the spec

Gate #8 is a good illustration of what a real validation layer does to a written spec. The field survey said the lockup release date must be ≥ the issue date. Then the gate met the corpus: in 31 of 62 rows a convertible bond states its transfer restriction as a duration (사모발행에 의한 1년간 …), not a date — and the rows that did carry a date carried one the model had computed. So the date is now derived deterministically from the API's 납입일 via mijual.calc.lockup_release_date, and any stated date is checked against it. A model-computed date stopped being an input and became something to disagree with.

The exposure contract

The verdicts are not consulted at render time by each surface; they are persisted, and everything above reads them:

  • an event is exposable iff it is not suppressed, not withdrawn, and carries no blocking flag (warrant_conflict, detail_conflict, event_key_collision, hint_split_evidence);
  • a field is renderable iff its gate verdict is passed or tbd.

Both live on columns (Event.exposure_state, Extraction.gate_status), so the board filters in SQL and no serving layer re-implements exposure. Suppressed events are retained with a suppressed_reason, never deleted — so a suppression is auditable and reversible.

The trust promise, and its published price

"A field that fails its gate is never shown" is cheap to say and expensive to mean. The project publishes the bill: ▷49.2억원 — 6.4% of its own headline number — is deliberately left off the total, because three offerings with a citable lapse count had their discount-rate extraction fail the citation gate. The headline is smaller than it could be, on purpose, and the document says by how much.

Verified on the live corpus rather than by test alone: 409 renderable field instances, 0 of them outside passed/tbd; 0 tbd fields leaking a value; 0 exposable events in a non-exposable state.

3.3 말하기 — the agent

The user-facing AI 질문 surface is an autonomous tool-calling agent, and that was a binding requirement rather than an implementation choice. The operator's words, recorded verbatim in the decision log: "we need to build a agent not just llm chain."

What makes that checkable rather than arguable is a control-flow property.

The property, stated so it can be grepped

No tool name appears in the control flow. Nothing is fetched before the model speaks or after it; no tool fires because a question matched a pattern; no ordering is imposed on the calls it asks for. call_tool is invoked from exactly one place in the whole codebase, dispatching on the name the model supplied. Even the reader's current 범위 (which filing they opened the widget from) is resolved with a plain row read and placed in the system instruction as context — specifically so that a scoped turn does not make one tool call mandatory.

There are seven tools: search_events, get_event, get_portfolio, save_feedback, get_contact, calculate and security_check. The last two are zero-I/O and therefore BUDGET_EXEMPT — and note how that exemption is expressed: as a frozenset declared beside the tools, which the loop asks about. The loop never names a tool even to exempt one.

The same discipline covers the one place where a call ends the turn early. A security_check call is a refusal, not a tool, and the loop stops on it — but it discovers this by asking security_incident(call.name, call.args) whether this call is an incident. The placement is precise and deliberate: after the stream returns and calls are collected, before the citation gate flushes, before the tool-budget check, and before any tool executes. So no tool of that round runs, no ModelMessage is appended (the model gets no second chance to soften its own refusal), prose still sitting in the gate's buffer never reaches the reader, and the turn cannot end as tool_budget when what happened was a refusal. The incident is logged — category, a 200-character excerpt, the anonymous session handle — and stored in no database table. The reader never learns a check happened.

What the loop keeps for itself

Autonomy is scoped, not total. The model decides what to call; the loop owns everything that must not be a model's decision: the visible tool fact rows, the citation gate, the signed refusal sentences (recognised, never generated), the answer footer and outbound links composed from tool results as data so the model never writes a URL, the structural budget, and the spend ledger.

The budget is TurnBudget(max_rounds=20, max_tool_calls=30, max_model_calls=22), with one non-cosmetic invariant pinned by a test: max_model_calls must stay ≥ max_rounds. The client's own ceiling fires inside a round, so a smaller model-call budget would abort reporting call_budget when what actually happened was round_budget — a ceiling that lies about which ceiling fired. Every cap maps to an honest terminal, and no ceiling is ever rendered as reader-facing copy.

The citation gate: strip, don't drop

This is the part of the system that was rebuilt in the light of production, and the story is instructive. The first version put a gate on the generation boundary and had it judge: a sentence whose markers did not resolve, or that cited nothing, or that stated a number no tool returned, was discarded before the reader saw it. Then the operator typed 「안녕」 — hi — and got back 「이 데이터는 검증을 통과하지 못했습니다」. A greeting has nothing to cite, so a citation-mandatory gate deleted it and the surface fell back to a refusal.

The boundary stayed; the judgement went. Under strip-don't-drop, the model's text still never streams to the reader — it streams into CitationGate — but what leaves is the prose the model wrote with everything unverifiable taken out of it rather than the sentence taken away:

InputWhat leaves
a marker naming an id a tool returneda numbered chip
a marker naming an id nothing returned, malformed, or cut in half by a dying stream nothing — and the sentence stands
an uncited sentence (a greeting, a confirmation, a meta answer) the sentence, unchanged
a 공시-shaped figure present in no tool payload the sentence, with the figure marked 「미확인」
a 「…」 span occurring verbatim in nothing a tool returned the words, without the quotation marks

That last row is the subtlest move in the file, and it generalises well. What the "never fabricate a quote" rule protects is not the words — it is the claim of being 원문. So strip the claim and let the words through as the assistant's own prose, where their figures are then traced like any other. The rule is satisfied, and nothing is silently deleted.

Consistently with that, blocked on the turn terminal counts removed markers, not dropped sentences. An operator watching that number is watching the model's citing behaviour; nothing the reader saw is missing because of it.

The limit the code states about itself

The figure check is membership, not semantics. A token that appears anywhere in any of the turn's tool payloads passes — so a value quoted in the wrong unit, or about the wrong field, passes too, and a turn that read a whole filing has a large permissible set. What it reliably catches is a figure that exists nowhere upstream, which is the shape of every computed, converted or invented one. The docstring says this out loud instead of letting the reader infer a stronger guarantee than exists.

Arithmetic is routed, not forbidden

The first version of the agent simply banned computation. That produced its own defect: a reader asking 「계산해 주세요」 got a refusal for wanting arithmetic. The fix was a calculate tool that is a window onto mijual.calc, never a second implementation — an op enum over five existing primitives (배정 신주 · 초과청약 한도 · 소멸 증서 · D-day · 전매제한 해제일) plus a clearly-labelled AST-whitelisted expression hatch. The system instruction now reads:

ARITHMETIC HAPPENS IN THE TOOL, NEVER IN YOUR PROSE.
...
What stays forbidden is doing the arithmetic **yourself** — adding, subtracting,
multiplying, converting or rounding in your head and writing the result down.
Nothing downstream computes either: the surface only draws what you and the tools
produced, so a number that went through no tool exists nowhere and reaches the
reader marked 「미확인」.

— src/mijual/agent/instructions.py, _CALCULATOR

The estimate family is deliberately not exposed through the calculator: an estimated value returned as a "calculation" result would silently lose its 「추정」 mark. And the reader's screen shows the calculation block drawn before the call runs, from the arguments themselves, then replaced in place when the result arrives — because auditability is half inputs and half result, and the inputs should be visible while the calculation is still pending.

The system instruction is a cache key

One more constraint worth copying. instructions._RULEBOOK is assembled once at import from static blocks, and system_instruction() appends only the turn's two changing values (the reader's 범위, and today's date in KST) at the tail. The prefix is therefore byte-identical across every turn of every session — asserted by a test that splits on the THIS TURN. seam. Any per-turn value placed above that seam silently defeats implicit prompt caching on every turn thereafter.

And the honest part: whether the prefix is actually being credited is measured, not assumed. The cached-token count rides the spend ledger end to end, and the measurement across live passes is cached 0 every time, with a roughly 5.5k-token prefix. The architecture document records that as an open question rather than as a claim that caching works.

3.4 The boundaries are tests, not prose

Through the pipeline-only era, the system's loudest invariant was "no OpenDART call and no LLM call happens in a request path" — published in three documents and in the service's own OpenAPI description. Then the agent arrived, and an agent streaming over SSE is a model call in a request path. There is a version of this story where the agent goes into a new top-level package, the existing import scans stay literally green, and the published sentence quietly becomes false. That was explicitly judged not good enough.

The sentence was rewritten into three clauses, each carried by its own AST import scan:

  1. No OpenDART call happens in any request path. A test walks every module under src/mijual/web/ and fails if one imports mijual.dart, mijual.collect or mijual.extract; the same scan is applied to the derivation layer.
  2. The model is reached only through mijual.agent. A test bans google / openai / anthropic anywhere under src/mijual/web/**, so the credential, the per-turn budget, the citation gate and the ledger cannot be bypassed by a handler that talks to the model API itself. It is a routing rule, not an absence.
  3. mijual.web speaks HTTP in exactly one file — and a fourth scan keeps spending modules out of mijual.agent too: the agent reads persisted rows, it never collects or extracts.

The old absolute wording was corrected everywhere it had been published, including the OpenAPI description, which is an outward surface. The reasoning recorded with the change is the part worth keeping: an invariant that is enforced by a test everyone trusts, but has silently stopped meaning what it says, is worse than no invariant.

Two more properties are tests rather than assertions:

  • "Agent, not chain" is a test. tests/test_agent_loop.py drives the real run_turn with a ~20-line scripted model client. A loop with a hardcoded pre-fetch would fail the case that asserts a turn can complete with no tool round at all.
  • Anonymity is a schema property. The two conversation tables carry no account, email, IP or user-agent column and no foreign key in either direction — and tests/test_web_conversations.py walks both tables' columns and every foreign key in the metadata rather than trusting a reviewer. So 「대화는 익명으로 저장됩니다」 moved from trivially true, nothing stored to implemented and checkable.

The whole suite — 26 files, around 170 test functions — runs in a few seconds against in-memory SQLite with no network, no database, no API key and no live model call ever. The agent tests run against a scripted model, so they spend nothing.

3.5 How accuracy is measured — and what the number does not mean

evalset/ holds a frozen, stratified sample: 344 (filing, field) rows over 99 filings, drawn deterministically and frozen with every row's value, quote, context and gate verdict. The report reads two JSON files and never the database, so a label stays meaningful after the corpus moves under it.

98.6%strict precision of what the product would show — 213/216 random picks, 95% Wilson CI [96–100%]
0wrong labels across all 344 rows (339 correct / 5 partial / 0 skip)
12.2%corpus-wide gate-block rate, 77 of 633 distinct rows

Both error directions are measured, which is rarer than it should be. Precision alone is a metric a gate can buy by blocking more, so the report also measures over-blocking: how often the gate threw away a reading that was right. The result is uncomfortable and published anyway:

Over-blocking: 100%

19/19 blocked rows in the random draw, and 48/48 across every pick, were judged correct readings. In this sample the gate bought no precision at all: it removed no error and removed 48 true statements. Of those 48, 30 are blocks the product wants anyway (field_absent, superseded_api_reference); 18 are actionable.

And the qualifier that governs every use of the accuracy number: these labels are cross-model judgements — Claude judging Gemini's extractions, at the operator's direction — and explicitly not human ground truth. Zero rows have been verified by a person.

That qualifier is mechanised rather than merely written down, which is the part I would copy directly. evalset/labels.json carries a judged_by block (judge / basis / imported_at); Labels.write() refuses to write an unstamped file; the import command requires --judged-by and never inherits it from the previous file, so a human re-judging a handful of rows cannot silently keep a machine's stamp; and the report prints what the file says rather than a hardcoded sentence. The decision log adds a prose consequence: no artifact may describe these labels as human ground truth, and the phrase "hand-labelled" is forbidden for them.

One more thing the report does well: it refuses to let a scary number travel without its split. The gate-block rate on ③ is 44%, which reads as "③ is badly extracted" — so the report states that of 11 blocked dissent_notice_procedure rows, 8 are superseded_api_reference, 1 is api_deadline_absent, 1 is field_absent, and exactly 1 is a real extraction mismatch. Likewise, all three strict misses turn out to be a single defect class: 실적보고서 figures correctly summed from two table rows but cited by one addend. The reading was right; the citation contract was too narrow.

4. Best practices & next steps

How much of this is idiosyncratic, and how much is prevailing practice arrived at independently? Mostly the latter — with two deliberate divergences worth naming.

Where it aligns with prevailing practice

Sentence-level, source-anchored citation is now a first-party feature elsewhere. Anthropic's Citations API chunks source documents into sentences, passes those chunks to the model, and produces responses with citations referencing those chunks — with one customer reporting source hallucinations falling from 10% to 0% (Introducing Citations on the Anthropic API — claude.com). Notably, the model references provided chunks rather than computing offsets into a document on its own. That is the same insight as inversion 1, reached from the other direction: the provider pre-commits the citable units; 주주의관제탑 lets the model quote freely and then resolves the quote itself. The latter buys provider independence — this system runs on Gemini — at the cost of owning the locator.

Schema conformance is understood as shape, not truth. Constrained decoding guarantees a parseable, schema-valid object and nothing about whether the values are right: "constrained decoding guarantees well-formed outputs, not well-informed ones" (A Guide to Structured Outputs Using Constrained Decoding — aidancooper.co.uk). The extraction layer's FieldSpec.schema gets exactly that much credit and no more, which is why a semantic gate sits behind every field. Many production pipelines stop at the schema and implicitly treat conformance as validation.

Autonomy with explicit stopping conditions. Anthropic defines agents as "systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks," notes that "the autonomous nature of agents means higher costs, and the potential for compounding errors," and recommends "stopping conditions (such as a maximum number of iterations) to maintain control" (Building Effective AI Agents — anthropic.com). TurnBudget(20, 30, 22) is precisely that recommendation, with the refinement that each ceiling maps to a distinct, honest terminal reason.

Static prefix, variable tail. Google's guidance for implicit caching is to "try putting large and common contents at the beginning of your prompt" and to keep variable content at the end, with documented per-model minimum input token counts (the page lists e.g. 4,096 for Gemini 3.8 Flash and 2,048 for Gemini 2.5 Flash) and a cached-token count reported in usage metadata (Context caching — ai.google.dev). The _RULEBOOK-then-THIS TURN. arrangement, and the test that splits on that seam, implement the guidance as a structural constraint rather than a convention.

Where it diverges — and why that can be right here

1. It builds an agent where the same guidance would suggest a workflow. Anthropic's advice is to prefer the simplest pattern that passes evaluation and reserve agents for open-ended problems "where it's difficult or impossible to predict the required number of steps." Answering "when does this warrant expire and what is it worth at my share count" from gate-passed rows is not obviously that problem — a retrieve → prompt → answer chain would plausibly have served, and would have been cheaper and lower-latency. The agent shape was an explicit operator requirement, adopted knowing the trade. What makes the divergence defensible rather than merely expensive is that the named risks are answered structurally: compounding error is bounded by budgets that each report which ceiling fired, and an autonomous turn cannot reach anything that spends or writes, because the tools are read-only and the import graph is scanned. It is also observably doing agentic work — on a search that returned nothing, the model corrected its own query and searched again unprompted.

2. Its accuracy number is cross-model, and it says so loudly. The literature is clear that LLM judges carry self-preference bias — one recent study of 20 models finds statistically significant bias in 17 of them, and explicitly notes that family effects "are not fully disentangled from pure self-preference," making it difficult to separate self-identification from shared stylistic and training characteristics (Quantifying and Mitigating Self-Preference Bias of LLM Judges — arxiv.org). Judging across families — Claude on Gemini — is the standard mitigation, and it is the right call given the alternative was no measurement. But it mitigates rather than eliminates, so the project's insistence that the figure is not ground truth is not false modesty; it is an accurate description of what the method supports. Mechanising the qualifier so it cannot be stripped downstream goes further than most teams bother to.

3. It intervenes at claim level, not turn level. The common safety posture is to block or regenerate a whole response that fails a check. Strip-don't-drop instead edits the response: markers leave, figures get marked, fabricated quotes lose their quotation marks, and the sentence survives. That is unusual, and the failure that motivated it — a greeting being answered with a verification error — is a good argument that turn-level gates over-trigger on the large fraction of traffic that has nothing to cite.

Next steps

  1. Buy a human anchor for the accuracy figure. The machinery is already there: overwrite column A of evalset/sheet.csv and re-run the import with a new --judged-by, and the report restates the new judge automatically. Even a stratified 50–80 rows would convert "98.6%, cross-model" into a human-anchored estimate with a stated interval, and — given the family-effect caveat above — that is the single highest-value hour available to this system's credibility.
  2. Act on over-blocking; it is the measured defect, and precision is not. The sample says the gate removed 48 true readings and zero errors. 18 of those are already diagnosed (stale API reference data, single-span citation for multi-line quotes, a quantified 개월 withheld for an underived 해제일), and all three strict misses share one root cause: a value correctly summed from two table rows cannot be expressed by a citation contract that permits one span. Letting a citation carry more than one span would close the strict-error class and part of the over-blocking class at the same time.
  3. Settle the cached 0 reading. The documented prefix rules are already satisfied, and the minimums are published per model, so a prefix in the 5.5k range should qualify on any current Flash-class entry. Either the measurement is reading the wrong field, the turns are too far apart to share a cache, or this model's floor differs — and the answer changes per-turn cost on a surface that is free and unlimited. Worth one deliberate experiment (back-to-back turns, same scope) rather than leaving it as an open question.
  4. Narrow the figure check from corpus-wide to field-scoped membership. Today a number passes if it appears anywhere in any payload the turn read. Carrying the field key alongside each traced value — which the tool results already know — would turn "this number exists upstream" into "this number is the value of the field this sentence claims," which is the gap the docstring already identifies as the honest limit.

5. Quiz

Five questions on the load-bearing ideas. Click an answer to see whether it holds.

1. The extractor asks the model for a verbatim quote and never for character offsets. Why?

A model-supplied span is "a second thing to verify" — and verifying it means looking at what is actually there, which is the search you were trying to avoid. A quote is a claim the code can test with find(). (Snapshots are content-addressed by SHA-1, so offsets into a stored snapshot are stable.)

2. The extraction prompt deliberately omits the value printed at 본문 label 11 (청약예정일), even though it is right there in the document. What breaks if you include it?

A check is only worth its cost if its reference value was unavailable to the thing being checked. The natural drift of prompt engineering — add context until quality improves — is exactly what silently makes a validation layer vacuous.

3. Under strip-don't-drop, what does the blocked count on a turn's terminal event actually measure?

The first option describes the previous design, which was retired precisely because it deleted sentences. Under the current gate nothing the reader saw is missing because of blocked; it is a window onto the model's citing behaviour, not a record of censorship.

4. Which change would actually violate the "agent, not chain" property as the codebase defines it?

The property is stated as a control-flow fact: no tool name appears in the loop, and nothing is fetched before the model speaks. A "just to be safe" pre-fetch would break the decision rather than optimise it — which is why even the reader's current 범위 is injected as context rather than resolved through a mandatory tool call.

5. The extraction accuracy figure is 98.6% strict (213/216). What does that number not establish?

Zero of the 344 labels are human-verified, and cross-family judging mitigates self-preference bias without eliminating it. The figure is also precision-only: pair it with the over-blocking measurement (48/48 blocked rows judged correct) to see the whole error surface, which is exactly why the report measures both directions.
