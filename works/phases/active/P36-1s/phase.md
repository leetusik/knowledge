- Hermes fit (S1, partial: no live answer yet, key rejected): Hermes can be confined. The API server offers only web_search, web_extract and the tool_search bridge over the MCP tools, and the bridge and agent loop block every other tool; a disabled tool still runs if dispatched by name, so a `reader-guard` pre_tool_call allowlist plugin plus `approvals.deny: ["*"]` must ship as a second layer. Opus 5.5 requests carry `output_config.effort: medium`. → [topics/hermes-fit.md](topics/hermes-fit.md) § Q1
- Serving (S1): FastAPI drives Hermes through `/v1/runs` (session_id = our thread id, events SSE, stop, Idempotency-Key), not `/v1/responses`, whose usage has no cache split; Hermes stays on the compose network and its own failure text never reaches readers. → [topics/hermes-fit.md](topics/hermes-fit.md) § Q5
- Saved chats (S1): Postgres is the source of truth (threads per user per document; messages with tool steps, citations, usage); Hermes sessions are a cache keyed by thread id, re-seeded with `conversation_history` if lost. FastAPI prices each run from `run.completed` usage for the spend cap. → [topics/hermes-fit.md](topics/hermes-fit.md) § Q5
- Knowledge-base key (S1): Hermes's MCP headers are fixed per profile (no per-session header), so Hermes sends one org-scoped service `vk_` key of the owning org and FastAPI enforces members-only before Hermes; paid users later = one Hermes profile per tenant. → [topics/hermes-fit.md](topics/hermes-fit.md) § Q3
- Web (S1): search on Brave free (1 query/s: a second search within about 1 s gets HTTP 429); page extract pinned to Firecrawl keyless; `keyless_fallback` and `keyless_rescue` off so no query or URL rotates to other vendors. → [topics/hermes-fit.md](topics/hermes-fit.md) § Q2
- Code access (S1): option B, a blobless partial clone read through git objects at a pinned commit by a read-only code MCP in its own container, with a one-shot prefetch of that commit's blobs (about 3 s, about the tree's size) so grep works. A rejected (code search found 0 of 3 known identifiers), C the fallback. → [topics/hermes-fit.md](topics/hermes-fit.md) § Q4
- Project-to-repos mapping (S1, proposal): a member-edited `project_repos` table in the accounts plane (provider, owner, repo, ref, pinned_sha); a document's `source_repo` is only a hint (local paths are cut to a basename). → [topics/hermes-fit.md](topics/hermes-fit.md) § Q4
