## Decisions

_Durable cross-slice decisions, one line each. Replace a superseded line; never stack versions. Contracts and signed-design summaries go to `topics/<slug>.md` beside this file, linked by one line._

- **Cut (DECOMP):** S1 `knowledge check` (high) → S2 skill uses it (low) → S3 explain-critic + chapter procedure (high) → S4 route + DECOMP/REVIEW references + install patch notes (high) → S5 one-chapter rehearsal (qa low) → S6 handoff (docs low) → REVIEW (gated). Code first so the package is written against a real command; the rehearsal before the handoff so the bootstrap gets a loop proven once. No research slice and no DECOMP2: exploration already located every touchpoint. Breakdown, triggers and estimate (~$70–75, ~4.5 span-hours): `topics/slice-breakdown.md`.
- **Publish first, then read (DECOMP; operator-approved with the plan):** there is no scratch reader outside this repo, so the explain REVIEW publishes every chapter **private** first, then reads the book in the real reader; fixes after that are republished as new versions. Supersedes the intent's "renders it in the reader, then publishes" order.
- **Private means a private project (DECOMP, from the code):** visibility is per project (`projects.visibility`, default `"private"`); a tenant-#1 / master-bearer write is public by definition (`ctx.is_public`). The explain REVIEW publishes with the operator's org credential into a project that is not public, never through tenant #1; making the book public stays the operator's act after acceptance.
- **A check never writes (DECOMP):** the dry run takes no `WRITE_LOCK`, writes no file, row, manifest, asset or commit, get-or-creates no registry project (so it must not depend on `ensure_registry_project`), and meters no usage event (sets no `request.state.usage`). It reuses the same validation function as `POST /api/documents`, so the two cannot drift.
- **The critic is dispatched by the main thread (DECOMP):** a slice executor may spawn only `Explore`, so a chapter slice is multi-span like a co-work critique step: executor drafts + checks → orchestrator dispatches explain-critic → executor revises once. S3 writes the procedure on that basis.
- **Package and handoff locations (DECOMP):** the package lives in `works/phases/active/P31/package/`, paths mirroring the bootstrap's `payload/` (`claude/agents/…`, `claude/skills/…`); the updated handoff is `works/phases/active/P31/handoff-explain.md`, self-contained and superseding P30's, which stays untouched as history of a done phase.
