_Intent: see [intent.md](intent.md)._

## Objective

Prepare, in this repo, everything the workflow needs to run explaining as a phase: (1) knowledge check — a CLI command and server endpoint that validates a chapter against the publish rules without publishing; (2) a ready-to-apply package for the bootstrap: the create-phase explain route, the DECOMP reference (research, book outline, an outline gate the operator signs), the per-chapter slice procedure (draft, validate, critic, one revision), an explain-critic agent, and the REVIEW reference (whole-book read, render in the reader, publish every chapter at once, private) plus the acceptance gate; (3) an updated handoff-explain.md. The bootstrap repo itself is out of scope; the operator relays the package.

## Decisions

_Durable cross-slice decisions, one line each. Replace a superseded line; never stack versions. Contracts and signed-design summaries go to `topics/<slug>.md` beside this file, linked by one line._

- **Cut (DECOMP):** S1 `knowledge check` (high) → S2 skill uses it (low) → S3 explain-critic + chapter procedure (high) → S4 route + DECOMP/REVIEW references + install patch notes (high) → S5 one-chapter rehearsal (qa low) → S6 handoff (docs low) → REVIEW (gated). Code first so the package is written against a real command; the rehearsal before the handoff so the bootstrap gets a loop proven once. No research slice and no DECOMP2: exploration already located every touchpoint. Breakdown, triggers and estimate (~$70–75, ~4.5 span-hours): `topics/slice-breakdown.md`.
- **Publish first, then read (DECOMP; operator-approved with the plan):** there is no scratch reader outside this repo, so the explain REVIEW publishes every chapter **private** first, then reads the book in the real reader; fixes after that are republished as new versions. Supersedes the intent's "renders it in the reader, then publishes" order.
- **Private means a private project (DECOMP, from the code):** visibility is per project (`projects.visibility`, default `"private"`); a tenant-#1 / master-bearer write is public by definition (`ctx.is_public`). The explain REVIEW publishes with the operator's org credential into a project that is not public, never through tenant #1; making the book public stays the operator's act after acceptance.
- **A check never writes (DECOMP):** the dry run takes no `WRITE_LOCK`, writes no file, row, manifest, asset or commit, get-or-creates no registry project (so it must not depend on `ensure_registry_project`), and meters no usage event (sets no `request.state.usage`). It reuses the same validation function as `POST /api/documents`, so the two cannot drift.
- **The chapter slice is three spans (DECOMP, written by S3):** a slice executor may spawn only `Explore`, so span 1 the executor researches (§3), drafts (§4), reads through (§4.8), runs `knowledge check` (§4.9) to exit 0 and returns `done` + `critic_ready: yes`; span 2 the orchestrator dispatches `explain-critic`; span 3 the executor (SendMessage, or re-dispatched from disk) answers every must-fix and the should-fixes it agrees with in one revision, re-checks and returns the final verdict. Span 3 always runs; no second critic round; a disputed must-fix goes to the REVIEW via `result.md`. One `record-dispatch` and one commit, after span 3. Package: `package/claude/skills/do-whole-phase/reference/explain-chapter.md`.
- **The critic's model: option (a), no engine change (S3):** `explain-critic` frontmatter `model: opus`, `effort: high`, tools `Read, Glob, Grep, Bash, Write, WebFetch, WebSearch` (no Edit). It always runs on a model different from the chapter's drafter: a mid (sonnet) chapter gets it as written, a high (opus) chapter gets `model: sonnet` passed per call; both rows on one model → STOP and tell the operator. No route-table row; a dedicated engine row (option b) is left for the bootstrap to decide. Package: `package/claude/agents/explain-critic.md`.
- **Book file locations (S3):** draft `book/<key>.md` (stands in for the skill's `<tmp>/body.md`), images `book/assets/<key>/`, critique `book/critique/<key>.md` (written once), long research notes `topics/<key>-research.md`, all under `works/phases/active/P<N>/`; the slice folder keeps only `plan.md` and `result.md`. A chapter's `result.md` carries a `## Publish` section (the exact `knowledge check` command; the REVIEW swaps `check` for `save`) and a `## Critique answers` section (`C01 · fixed | disputed | declined · …`).
- **Package and handoff locations (DECOMP):** the package lives in `works/phases/active/P31/package/`, paths mirroring the bootstrap's `payload/` (`claude/agents/…`, `claude/skills/…`); the updated handoff is `works/phases/active/P31/handoff-explain.md`, self-contained and superseding P30's, which stays untouched as history of a done phase.

- **OQ2 (P31.S1):** decided: the check reports every refusal a publish would meet — the 422s, the existence/stem/migration 409s, and the chapter-binding 409s `_place_variant` raises under the publish's lock (run on the check without the lock; it only builds the manifest). - **OQ3 (P31.S1):** decided: `knowledge check --json` prints only an ok's 200 on stdout; a refusal stays on stderr as `error: …` with exit 1, keeping the CLI's documented protocol ("errors are never JSON", `knowledge guide`). - **OQ4 (P31.S2):** decided: the skill's check is a new §4.9 placed after the read-through, run with the publish's exact flags and without `--json`; on exit 2 (no route / old CLI) it is skipped with a report line and §5's 422 branch remains the backstop, since production has no route until OQ1 is done.
- **OQ5 (P31.S3):** decided: a chapter's images live at `book/assets/<key>/` and its exact publish flags in its `result.md` `## Publish` section (the `knowledge check` command it ran), so the REVIEW's private publish of every chapter at once re-sends what was checked. The plan pinned the draft and critique paths but not these. Unattended choice; revisit at the review.
- **OQ6 (P31.S3):** decided: span 3 always runs, even on a critic `pass`, so every chapter's `result.md` records how each finding was answered (`fixed | disputed | declined`) and carries the final verdict; a `should-fix` the executor declines is recorded with its reason. Unattended choice, costs one short resumed span per clean chapter.
