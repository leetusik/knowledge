# Phase P34-n0: Keep private documents off the public repo

_Intent: see [intent.md](intent.md)._

## Objective

Stop the knowledge server from committing and pushing private projects' documents to the public GitHub repo (today it decides by owner account, not by project visibility), deal with what is already exposed there, and keep private titles out of the published home index.

- **Exclude block (S1):** the checkout's `info/exclude` (found with `git rev-parse --git-path`) holds a managed block between fixed markers (`# >>> knowledge server: private projects ...`), three sorted lines per private project: `/docs/<p>/`, `/docs/.versions/<p>/`, `/docs/.books/<p>/`. `gitops.write_private_projects` always rewrites it whole; `mark_private` adds one; lines outside the markers are kept. Never a tracked file.
- **Guard fails closed (S1):** `gitops.add`/`remove` raise `GitError` before staging when a path is in a marked footprint or an ancestor (`docs`, `docs/.versions`, `docs/.books`, the root), or when `docs/index.md` links into a marked project. Pathspecs are literal; the message names no project. The write stays on disk with `committed: false` and `commit_error`.
