# Phase P34-n0: Keep private documents off the public repo

_Intent: see [intent.md](intent.md)._

## Objective

Stop the knowledge server from committing and pushing private projects' documents to the public GitHub repo (today it decides by owner account, not by project visibility), deal with what is already exposed there, and keep private titles out of the published home index.

- **Publish rule (DECOMP):** a tenant #1 write publishes (commit, index bullet, landing) only when its registry project is `public`. A missing row or a failed lookup counts as private (fail closed). Legacy mode is unchanged. New projects start private (the registry default), so they publish only once toggled public (OQ1).
- **Footprint (DECOMP):** a project's published footprint is `docs/<p>/`, `docs/.versions/<p>/`, `docs/.books/<p>/` and its bullets in `docs/index.md`. Every gate, guard, exclude block, reconcile and purge covers all four, acting only on registry projects, never on other `docs/` dirs. → [topics/publish-paths.md](topics/publish-paths.md)
- **Publish gate module (S1):** `server/publish_gate.py` holds the one rule (`decide`, `publish_decision`, `project_publishes`, the worker wrapper `publish_decision_from_worker`) and `hide_private_project`. The save takes it from `ensure_registry_project` (now `RegistryProject(id, publish)`); the deletes and the book PUT use the worker bridge. A tenant #1 registry failure saves unpublished with a `commit_error` and marks the project.
- **Exclude block (S1):** the checkout's `info/exclude` (found with `git rev-parse --git-path`) holds a managed block between fixed markers (`# >>> knowledge server: private projects ...`), three sorted lines per private project: `/docs/<p>/`, `/docs/.versions/<p>/`, `/docs/.books/<p>/`. `gitops.write_private_projects` always rewrites it whole; `mark_private` adds one; lines outside the markers are kept. Never a tracked file.
- **Guard fails closed (S1):** `gitops.add`/`remove` raise `GitError` before staging when a path is in a marked footprint or an ancestor (`docs`, `docs/.versions`, `docs/.books`, the root), or when `docs/index.md` links into a marked project. Pathspecs are literal; the message names no project. The write stays on disk with `committed: false` and `commit_error`.
- **Reconcile (S2):** `server/reconcile.py` `reconcile()` acts only on the registry names it is given. Private: exclude block first, footprint untracked (`gitops.untrack`, files stay on disk), index lines into any marked project removed, index staged. Public (marked, or with stageable files): unmark, landing, bullets from the DB, stage; re-marked on failure. One commit per run, only when staged; unpublish messages name nothing. → [topics/reconcile.md](topics/reconcile.md)
- **Reconcile CLI (S2):** `docker exec knowledge-api python -m server.reconcile [--dry-run] [--push]`, run only while writes are paused. It refuses in legacy mode; an unreadable registry or unresolved tenant #1 exits 3 with no change (unknown never means unpublish everything); it waits ~10 s for `index.lock`; `--dry-run` writes nothing; only `--push` pushes. Its output names projects on the terminal only. → [topics/reconcile.md](topics/reconcile.md)
- **Toggle and lock (S2):** `WRITE_LOCK` and the push task moved to `server/write_lock.py` (`main` re-exports both names). The toggle reconciles a tenant #1 project after the registry update, under the lock in a threadpool, then queues the push like a write. Postgres first, git second: a git failure keeps the new visibility and returns a stage-only `"publish".error`; other tenants are unchanged.
