# P30 decided Operator Questions, full text

Moved word for word from `phase.md` → `## Operator Questions` by P30.S5 to keep the notebook under budget. Each entry there is collapsed to one line that points here. The review routes them from `phase.md`.

- **OQ1 (P30.S2):** Should a chapter variant name its document by `rel_path` or by a bare stem? (The plan said "stems"; P29 *Chapter* says `rel_path`.) — **decided:** `rel_path`, as in P29's contract. S5's html → native migration re-points the variant, as P29 says. Detail: `slices/P30.S2/result.md`.
- **OQ2 (P30.S2):** When a publish names a book or chapter that already exists, does it update that book's title, kind or subject, or that chapter's position, title or source? — **decided:** no. The manifest is authoritative, the request only seeds a NEW book or chapter, and `PUT /api/books/{project}/{book}` is the way to edit them. This is the most conservative option: a re-explain can never silently retitle or reorder a book.
- **OQ3 (P30.S2):** When a document bound into a chapter is deleted, should its manifest binding go too? — **decided:** the delete path is unchanged. Reads leave out a variant whose document is gone, a re-publish of that `(book, key, lang)` re-points it, and a `GET`→`PUT` round trip drops it. S8 (deleting a document purges readers' notes) may revisit this if it needs the binding removed.
- **OQ4 (P30.S3):** P29 says the svg block's "body is one `<svg>` element, plus `label`", but every typed body is YAML. What is the svg block's shape? **decided:** a YAML mapping, `{svg: <source>, label, caption?}`, the same shape as the figure row's svg item.
- **OQ5 (P30.S3):** Should ingest accept an unknown callout type, tone, shape, diagram kind or chart type and render it by the fallback (P29 says an unknown alert renders as NOTE, and `03-diagrams` calls this "P30's call"), or reject it? **decided:** reject it with a 422. This is the stricter option. The renderer keeps the fallbacks as defence in depth. An edge or step naming an unknown node is also a 422 (`diagram-ref`).
- **OQ6 (P30.S3):** Ids carried inside YAML conflict: P29 *Quiz* says item ids are required, while *Ids* mints `item-<n>`. What is the scope of a quiz option id? **decided:** quiz item, option and sources item ids are required, so `item-<n>` is never minted. Item and sources ids share the document namespace. Option ids are unique within their item (the signed quiz round's `answer: [b]`).
- **OQ7 (P30.S3):** What do h1, h5, h6 and headings or typed blocks nested in lists, quotes or callouts do? **decided:** every one is rejected. The title comes from the header, sections are h2–h4, and typed blocks and id'd code sit at the top level only, so every section boundary is a top-level block.
- **OQ8 (P30.S3):** What do annotation offsets measure? P29 *Anchors* points at the search projection; the signed `05-annotations` round defines a section's text as its passage containers. **decided:** the signed round. Sections are id'd top-level blocks, and the text is paragraphs, callout titles, table cells and code joined by "\n", with headings and typed-block text contributing nothing. There is no whitespace collapse (the plan's guess), and offsets count code points. Search uses a separate, wider `search_text`. Three related choices, also strict: GFM bare-email autolinks become `mailto:`, which is rejected; svg `class` is limited to `kb-fill-<tone>`/`kb-stroke-<tone>`; and an asset name is `[A-Za-z0-9][A-Za-z0-9._-]{0,127}` (S4 adopts it).
- **OQ9 (P30.S4):** P29 says JPEG and WebP metadata are stripped "(a P30 dependency choice)"; the plan says re-encoding must keep the pixels or the format is rejected. Re-encoding a JPEG or lossy WebP with Pillow is lossy. How are images stripped? — **decided:** at the container level, never by re-encoding, for all four formats (JPEG APPn/COM, PNG ancillary chunks, WebP EXIF/XMP, GIF comments and non-loop application extensions). The stripped bytes are decoded and compared with the original's pixels, and a mismatch is a 422. An EXIF orientation other than 1 is written back as an orientation-only block, so a phone photo still displays upright with its GPS, camera and time tags gone. No format is rejected. Pillow 13 is added for decoding, the size and the GIF still only.
- **OQ10 (P30.S4):** P29 draws a still frame only for an animated GIF. What happens to an animated PNG or WebP? — **decided:** rejected with `asset-animated` (the stricter option), so every animated image has the still the reduced-motion rule needs.
- **OQ11 (P30.S4):** P29 says `Cache-Control: private` unless the project is public, with no lifetime. — **decided:** `private, max-age=300`, or `public, max-age=300` only when the read came through the public path. The bytes are immutable, so the only staleness is a revoked right to read, and five minutes bounds it. The BFF relay re-asserts the same two values.
- **OQ12 (P30.S4):** Does a new version inherit the previous version's images, and may any document format carry assets? — **decided:** no inheritance: a version's map is exactly what its publish sent, and the archived version keeps its own map and files (P29). A re-explain re-sends its images, and S5's unknown-`asset:` 422 catches a missing one. An `html` document may not carry assets (`asset-format`: its sandbox could not load them); `md` may until S5 decides for `native`.
- **OQ13 (P30.S4):** Limits and deploy settings P29 does not state. — **decided:** a 40-megapixel cap per image (`asset-dimensions`, the decompression-bomb guard; an 8K screenshot fits); the 12 MB total counts decoded bytes; `deploy/knowledge.conf` raises `client_max_body_size` 5m → 20m (12 MB base64-encoded is about 16 MB) and adds the regex location that steers the asset relay to the web app. Both take effect at the next deploy, on the operator's word.
