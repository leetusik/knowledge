- **OQ1 (P30.S2):** Should a chapter variant name its document by `rel_path` or by a bare stem? (The plan said "stems"; P29 *Chapter* says `rel_path`.) — **decided:** `rel_path`, as in P29's contract. S5's html → native migration re-points the variant, as P29 says. Detail: `slices/P30.S2/result.md`.
- **OQ2 (P30.S2):** When a publish names a book or chapter that already exists, does it update that book's title, kind or subject, or that chapter's position, title or source? — **decided:** no. The manifest is authoritative, the request only seeds a NEW book or chapter, and `PUT /api/books/{project}/{book}` is the way to edit them. This is the most conservative option: a re-explain can never silently retitle or reorder a book.
- **OQ3 (P30.S2):** When a document bound into a chapter is deleted, should its manifest binding go too? — **decided:** the delete path is unchanged. Reads leave out a variant whose document is gone, a re-publish of that `(book, key, lang)` re-points it, and a `GET`→`PUT` round trip drops it. S8 (deleting a document purges readers' notes) may revisit this if it needs the binding removed.
- **OQ4 (P30.S3):** P29 says the svg block's "body is one `<svg>` element, plus `label`", but every typed body is YAML. What is the svg block's shape? **decided:** a YAML mapping, `{svg: <source>, label, caption?}`, the same shape as the figure row's svg item.
- **OQ5 (P30.S3):** Should ingest accept an unknown callout type, tone, shape, diagram kind or chart type and render it by the fallback (P29 says an unknown alert renders as NOTE, and `03-diagrams` calls this "P30's call"), or reject it? **decided:** reject it with a 422. This is the stricter option. The renderer keeps the fallbacks as defence in depth. An edge or step naming an unknown node is also a 422 (`diagram-ref`).
- **OQ6 (P30.S3):** Ids carried inside YAML conflict: P29 *Quiz* says item ids are required, while *Ids* mints `item-<n>`. What is the scope of a quiz option id? **decided:** quiz item, option and sources item ids are required, so `item-<n>` is never minted. Item and sources ids share the document namespace. Option ids are unique within their item (the signed quiz round's `answer: [b]`).
- **OQ7 (P30.S3):** What do h1, h5, h6 and headings or typed blocks nested in lists, quotes or callouts do? **decided:** every one is rejected. The title comes from the header, sections are h2–h4, and typed blocks and id'd code sit at the top level only, so every section boundary is a top-level block.
- **OQ8 (P30.S3):** What do annotation offsets measure? P29 *Anchors* points at the search projection; the signed `05-annotations` round defines a section's text as its passage containers. **decided:** the signed round. Sections are id'd top-level blocks, and the text is paragraphs, callout titles, table cells and code joined by "\n", with headings and typed-block text contributing nothing. There is no whitespace collapse (the plan's guess), and offsets count code points. Search uses a separate, wider `search_text`. Three related choices, also strict: GFM bare-email autolinks become `mailto:`, which is rejected; svg `class` is limited to `kb-fill-<tone>`/`kb-stroke-<tone>`; and an asset name is `[A-Za-z0-9][A-Za-z0-9._-]{0,127}` (S4 adopts it).
- **OQ9 (P30.S4):** P29 says JPEG and WebP metadata are stripped "(a P30 dependency choice)"; the plan says re-encoding must keep the pixels or the format is rejected. Re-encoding a JPEG or lossy WebP with Pillow is lossy. How are images stripped? — **decided:** at the container level, never by re-encoding, for all four formats (JPEG APPn/COM, PNG ancillary chunks, WebP EXIF/XMP, GIF comments and non-loop application extensions). The stripped bytes are decoded and compared with the original's pixels, and a mismatch is a 422. An EXIF orientation other than 1 is written back as an orientation-only block, so a phone photo still displays upright with its GPS, camera and time tags gone. No format is rejected. Pillow 13 is added for decoding, the size and the GIF still only.
- **OQ10 (P30.S4):** P29 draws a still frame only for an animated GIF. What happens to an animated PNG or WebP? — **decided:** rejected with `asset-animated` (the stricter option), so every animated image has the still the reduced-motion rule needs.
- **OQ11 (P30.S4):** P29 says `Cache-Control: private` unless the project is public, with no lifetime. — **decided:** `private, max-age=300`, or `public, max-age=300` only when the read came through the public path. The bytes are immutable, so the only staleness is a revoked right to read, and five minutes bounds it. The BFF relay re-asserts the same two values.
- **OQ12 (P30.S4):** Does a new version inherit the previous version's images, and may any document format carry assets? — **decided:** no inheritance: a version's map is exactly what its publish sent, and the archived version keeps its own map and files (P29). A re-explain re-sends its images, and S5's unknown-`asset:` 422 catches a missing one. An `html` document may not carry assets (`asset-format`: its sandbox could not load them); `md` may until S5 decides for `native`.
- **OQ13 (P30.S4):** Limits and deploy settings P29 does not state. — **decided:** a 40-megapixel cap per image (`asset-dimensions`, the decompression-bomb guard; an 8K screenshot fits); the 12 MB total counts decoded bytes; `deploy/knowledge.conf` raises `client_max_body_size` 5m → 20m (12 MB base64-encoded is about 16 MB) and adds the regex location that steers the asset relay to the web app. Both take effect at the next deploy, on the operator's word.

## P30.S9

- **OQ31 (P30.S9):** What does the re-anchoring write-back rewrite? The plan adds "the new offsets when found"; P29 says only that `anchor_status` and `anchored_version` are written back. — **decided:** only those two columns. The captured anchor (`block_id` and `quote`: exact, prefix, suffix, start, end) is never rewritten, and every read resolves from it against the version on screen. So a fuzzy match never compounds across versions, a `block` or `orphan` comes back by itself if a later version restores the text, and the signed "Made on {Language} v{n}" and "Read this section in v{n} →" stay true (the row's `lang`/`version` plus its original `block_id`). `updated_at` is not bumped: it stays the reader's own edit time. This is the option that can never lose or distort a reader's annotation.
- **OQ32 (P30.S9):** What does `anchored_version` mean once the ladder runs? — **decided:** the newest version on which the ladder found the text (exact, fuzzy or moved); it does not move on `block` or `orphan`. It is written only by a read of the document's current version, only for the caller's own rows, only when it or the status changes, and never over a result computed against a newer version (`anchored_version <= target` in the UPDATE). An old-version read (`?v=`) resolves for that version and writes nothing.
- **OQ33 (P30.S9):** The fuzzy method. P29 says only "similarity ≥ 0.8 over the quote with its context". — **decided:** similarity = 1 − Levenshtein distance / the longer length (bit-parallel Myers in pure Python, no new dependency). A hit needs ≥ 0.8 on both the quote alone and on prefix + quote + suffix against the candidate span widened by the prefix's and suffix's lengths: the quote-alone bar stops unchanged context from carrying a short, changed quote onto other words. Candidates rank by context similarity, then quote similarity, then nearness to the stored `start`, then position. A quote under 4 characters never matches fuzzily. "Moved" is an exact match only, ranked by how much stored context it repeats, then document order.
- **OQ34 (P30.S9):** Edge cases P29 leaves open. — **decided:** (a) a block note (no quote) on a retired id is `orphan` (P29 rung 5), never re-homed; (b) a section bookmark whose id is retired falls back to the nearest preceding id of the version it was made on (`place.exact: false`), else no section: bookmarks have no orphan state and are never dropped; (c) a version whose source is not native, whose archive row is missing, or which no longer parses is not resolved: the stored anchor is reported with `method: "stored"` and nothing is written, so a stricter future parser or a missing archive can never orphan a chapter; (d) another language's annotations are resolved in their own variant's current version (their status written back) and only their section is mapped onto the variant on screen; they are never painted; (e) `resume` maps the unit's latest position (any variant) onto the variant on screen by id, else its fraction; (f) the payload changes are additive except that the reads split orphans out of `annotations` into `unanchored` (no client consumed S8's shape yet).

- **OQ39 (P30.S10):** Where does idempotence keep a review's result, with S8's tables fixed? — **decided:** `review_id` is the `review_logs` row id, and the log's `response` jsonb is `{answer, due, state}` (plus `seeded_by` on a seeding log), so a repeated id writes nothing and returns the stored outcome with current counts (`replayed: true`). A `review_id` already used for another card, or a rating on a suspended card, is a 409; another user's id, a retired card or an unreadable one is the 404. `state_before` 0 means never reviewed. No migration.
- **OQ40 (P30.S10):** How are drift and readability resolved with a `unit` that can lag? — **decided:** lazily, on every queue read and card write, through the gate: a `d:<doc>` card resolves through that document (also once it is bound into a book); a `c:<book>/<key>` card through the book's live variants of that chapter, so a chapter removed from its book hides its cards (kept, not deleted) until it is bound again. A card renders in the reader's last-used language (newest position), else its own, else `en`. A changed `type` resets the card (FSRS new, logs kept, `reset: true`); an id gone from EVERY readable variant's current version, each one parsed, retires it; an unparseable or non-native version decides nothing and the card is just not shown.
- **OQ41 (P30.S10):** Additions beyond P29's payloads. — **decided:** the queue adds `profile` and `limit_reached`; `where` adds `chapter_index`, `chapter_count`, `block_id`, `quiz_title`, `item_index`, `item_count` (08-review 11), and `block_title`, `annotation_id` for a highlight; a highlight's `front` adds `context` (80 characters each side, from the resolved section, else the stored prefix and suffix), `anchor` and `lang`; a card adds `status`, `reset`, `last_review`, `created_at`; the review reply adds `due_today`, `previews`, `next` (the queue head), `replayed` and `day`; every annotation carries `review`; `href` is `/@{org}/{project}/books/{book}/{key}?lang=…#{block}`, `/@{org}/{project}/{slug}#{block}`, or `/documents/{id}#{block}` for a slug-less tenant.

- **OQ56 (P30.S13):** The chrome rules ("hide on a scroll down of more than 4px, show on a scroll up of more than 12px") against slow or momentum scrolling that moves 1px per event. — **decided:** the thresholds are measured over the accumulated same-direction run (`stepChrome`), a reversal starts a fresh run; shown when under 48px from the top or within 4px of the bottom; 450ms quiet; ignored while a sheet is open; a tap on the text toggles. A hash jump (a contents entry, an `#id` link) lands at once (`scroll-behavior: auto` under `.rd-root`) so the jump is not read as the reader's scroll.
- **OQ57 (P30.S13):** Where do links the shell draws but other slices own point? — **decided:** the library link (`LIBRARY_HREF`) is `DEFAULT_NEXT_PATH` (`/dashboard` until S22 moves it to `/library`); the book-page link ("Book") points at the book URL, dead until S23; html chapters on the chapter route redirect to the legacy frame (`/documents/{id}`), and the old frame's document actions are not carried into the reader (S25 retires the frame).
- **OQ58 (P30.S13):** What does a missing chapter return, given `loading.tsx` streams? — **decided:** the page `notFound()` renders the §16 not-found view; because the segment has a `loading.tsx` the response is HTTP 200 with `noindex` (Next streams the shell first). A private, missing, wrong-org or unknown-project chapter renders the identical view (checked: same text, only build ids differ), so nothing leaks.
- **OQ59 (P30.S13):** Loose documents and md in the reader. — **decided:** md renders through the pipeline's md mode with no stand-in `h1` (the document's own headings stand); native loose documents show the title as `h1`; `doc:`/`chapter:` refs are pre-resolved for this reader (token capped at 40 refs) and anything unresolved stays a missing link; the language of a loose document is guessed (`guessLang`: Hangul present means `ko`); `?v=` falls back to the version read.
- **OQ60 (P30.S13):** How are the reading faces delivered? — **decided:** vendored as Google's own unicode-range woff2 subsets under `web/public/fonts/reader/` (Literata ×14, Noto Serif KR ×124, ~6.8 MB, OFL), declared in `reader-fonts.css` and imported only by the reader frame (a page loads just the subsets its text needs); not `next/font`, which cannot carry `unicode-range`.
- **OQ61 (P30.S13):** The dev CSP blocked the reader's own scripts. — **decided:** Next 16 dev (Turbopack) emits the `loading.tsx` and chunk `<script src>` tags without the nonce, so under `'strict-dynamic'` the reader never hydrated in dev. `readerCsp(nonce, dev)` drops `'strict-dynamic'` in dev (same-origin scripts trusted, beside `'unsafe-eval'`); production is unchanged and nonces every script (verified on the production build).
- **OQ62 (P30.S13):** What does "Try again" do on the failed state? — **decided:** it shows the skeleton at once and reloads the page (a bare `reset()` re-renders the same failed server payload, and `router.refresh()` in a transition stalled on the skeleton in dev); the reference shown is the error digest.

## P30.S14

- **OQ63 (P30.S14):** §7 says a callout body's first child sits `xs×k` below the head, "paragraphs, lists and code sit `sm×k` apart"; the canvas's own cascade (`.rd-callout .rd-p`, `.rd-list`, `.rd-code` after `.rd-callout__body > :first-child`, equal specificity) makes a first paragraph, list or code block measure `sm×k`. Which wins? — **decided:** the canvas wins (the prompt says so where they disagree): the first block takes `xs×k` only when it is not a paragraph, list or code block; those take `sm×k` wherever they sit in the body.
- **OQ64 (P30.S14):** The version line's "Version history" link-button opens the Version history sheet, whose content is S15's, and the frame has no such sheet yet. — **decided (undrawn gap; nearest drawn pattern):** S14 builds the drawn control (a link-button in accent, `aria-haspopup="dialog"`, shown when the variant has more than one version) as a small client island that announces `reader:open-sheet` with `{sheet: "versions", opener}` on the window; S15 adds the sheet and the listener (opening it, focus returning to `opener`). Until S15 lands, pressing it does nothing. Nothing else in S14 is waiting on it.
- **OQ65 (P30.S14):** How does an `md` document open? The canvas's "Plain Markdown" page uses the same opening as a chapter, but the stored md starts at its own H1. — **decided (nearest drawn pattern):** every document opens with the signed opening ("DOCUMENT" and the project name for a loose one, the title in the display face, the version line, no lede because md has no `summary`); the md body's own leading H1 is left out when its text is the document's title (`omitTitle`), any other H1 in an md body sets like an h2. md headings carry no ids, so an md document shows no "In this document" contents.
- **OQ66 (P30.S14):** Wide or scrolling blocks needed client measurement and a different markup from S12's, and the canvas gives `tabindex`/`role` to a drawing always but to a table only when it is a box. — **decided as drawn:** `TableBox` and `ArtBox` (client islands, `web/src/components/reader/scroll-box.tsx`) render the frame, the fades and the hint around server-rendered children; whether a box scrolls is measured (re-read on scroll, resize, the table's own resize, a text-size/theme class change on the reader root and when fonts load). A `text` fence is a drawing (`tabindex=0`, `role=region`, "Drawing, scrolls sideways"); a table is a region only when it is wide (8+ columns), long (more than 20 rows) or measured wider than its box; an ordinary code block wraps and is no longer a tab stop. A table that is both wide and long carries both classes, so the long rule's box applies to it.
- **OQ67 (P30.S14):** Spacing the canvas never draws: paragraphs inside list items and blockquotes, `h1`s past the opening in an md body, and the blocks S16-S19 own (figures, svg, quiz, sources, the diagram body). — **decided (undrawn; nearest drawn pattern):** a tight item's paragraph has no margin and a loose item's later blocks sit `sm×k` apart (the callout's step); a blockquote's first paragraph sits flush; an md `h1` takes the h2 style; S16-S19's blocks keep a `lg×k` column margin and S12's plumbing until they draw their own (the diagram slot itself takes `lg×k` like a code block, and its figure carries the title as its accessible name).
- **OQ68 (P30.S14):** The "Older translation" notice needs the source's newest version, and its action "Read English v2 →" opens the source "at the same section". — **decided:** the notice shows only on the translation's current version (the book read's `translated_from` describes that version, so an archived one cannot be judged) and only when the source variant's version is higher; both notices' actions are plain links (`?lang=` for the source, no `?v=` for the newest) at the top of the target, since the notice sits at the top of the page and so does the reader when it is in view.

## P30.S15

- **OQ69 (P30.S15):** "2 s after scrolling stops and at most every 15 s" (P29 cadence) could mean a rate limit or a maximum wait. — **decided:** a debounce of 2 s with a 15 s maximum wait (the write is due 2 s after the last scroll, and never later than 15 s after the first unsent one), so a long continuous read is still saved every 15 s. Opening a chapter is itself a first position (it creates the `started` row). On `pagehide`/`visibilitychange: hidden` the beacon sends what is pending; leaving by a link inside the app sends the last sample taken (never a fresh one: by then the DOM is the next page's).
- **OQ70 (P30.S15):** Which transport carries which write? — **decided:** the cadence write, the immediate `finished` write, Mark as finished and Mark as unread are the server action `saveReaderPosition` (P29: "through a server action"); only the `pagehide` beacon is the route handler (it cannot call an action), and `unread` is never sent by the beacon. Mark as finished and Mark as unread are optimistic and undone if the save is refused; the automatic finish is undone too, so "Saved to your progress" is never shown for a write the server refused.
- **OQ71 (P30.S15):** What is "the topmost visible id'd heading or block", and where does the page open? — **decided:** the last `[data-block]` (a heading or any id'd block) whose top is above the section line (the top bar's bottom edge + 24px). It opens with that block's top 16px under the top bar, chrome shown. The pill names the nearest preceding heading (h2-h4) as the canvas names a section; where there is no section to name (an `md` document has no ids, or the saved id is gone) the pill reads "Picked up where you left off · 45%" (undrawn; the nearest drawn pattern is the legacy reader's signed pill with a percentage, P29 *Three resume lines*). The pill is for a started chapter only, never on an older version, never when a link names a place.
- **OQ72 (P30.S15):** Mark as finished / Mark as unread pressed while reading an OLDER version ("reading an older version writes nothing"). — **decided:** the explicit marks still write (the reader asked), recorded against the version on screen (the server then shows "Updated" for a finish on an older version); the automatic writes (cadence, end-of-chapter finish) never run on an older version.
- **OQ73 (P30.S15):** The Version history sheet's data and its stale-translation flag. — **decided:** the history (the index's superseded rows plus the live version, newest first) is read with the page and degrades to the drawn "Unavailable" state; "Translated from English v1" shows on the current row only, because the version index does not carry an archived version's `translated_from` (an observation, not built around); the stale-translation flag is S14's "Older translation" notice (a translation whose `translated_from` lags its source, on its current version): the sheet draws no second flag. A row's date is its own `date`, the live row's the document's.
- **OQ74 (P30.S15):** The language switch's landing. — **decided:** a member's pending position is written first, then the switch navigates to `?lang=&#<section being read>`. The other variant lands on that hash; when the id does not exist there, a member lands on the server's mapped `resume` (S9: the nearest preceding id, else the fraction) and a signed-out reader on the top (the ids of a translation are kept by S2, so the common case is exact).
- **OQ75 (P30.S15):** A member reading a loose document whose owner has no org slug (no `canonical_path`, reached by `/documents/{id}`): the reader state API addresses a document by org, and the page has neither the slug nor the tenant id. — **decided (undrawn; safest option):** nothing is saved for that reader and the status row is left out of the end (the end mark, the library button and the rest stay). It does not arise for a tenant with a slug (every pretty URL and canonical path carries it).
- **OQ76 (P30.S15):** The page `<title>` against the "static title, `generateMetadata` costs a second uncached fetch" rule. — **decided:** `generateMetadata` on the three reader pages sets the chapter or document title ("<title> · knowledge" through the site template), and the metadata and the page share ONE load per request through React `cache` (`loadChapterReaderOnce`, `getDocumentOnce`, `resolveDocumentOnce`), so no second upstream read; a miss or a fault falls back to the static "Documents". The id and pretty pages also title an html document (they serve it).
- **OQ77 (P30.S15):** The next-chapter block's lede needs the next chapter's header, which the book read does not carry. — **decided:** one extra read of the next chapter's document with the page (only a native next chapter, degrading to no lede on any fault), taken in parallel with the other reads.
