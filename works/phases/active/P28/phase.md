## Decisions

_Durable cross-slice decisions. Replace a superseded line; never stack versions._

- **Nine middle slices, all `high`, cut on the contracts' own section seams.** The four `build-prompt.md`
  files are the binding spec, so the seams are theirs: R03 splits at §5 (the foundation vs. the system
  states — different files, different copy, D28 lands only in the second), R04 at §4.6/§4.7 (the pages that
  carry the new documents panel vs. the disclosure/search/auth work), R06 at §3.1/§3.2 (screen vs. paper —
  a different medium, a separate 7-check acceptance list, and the only slice that needs A4/Letter × light/dark).
  **Round 05 is deliberately NOT split** although it is the largest single job (contract 687 ln, `graph-canvas.tsx`
  1711 ln): §4.2's persisted `sessionStorage` record carries `legendOpen` (§4.3), `activeProject` (§4.4) and
  the tag lens (§4.6), so a split would have the first half write a record shape for behaviour it does not
  implement, and would pay the graph's browser verification twice. (P28.DECOMP)
- **The order 03 → 04 → 05 → 06 is forced by the cascade, not by taste.** Each round declares the earlier
  rounds' stylesheets *Do not touch* and layers on top of them: `kb-tokens.css → kb-console.css →
  app-frame.css → kb-console-responsive.css (R03) → kb-console-r4.css (R04) → graph-r5.css (R05) →
  kb-docview.css → kb-print.css (R06)` (R06 §1). No two apply slices may be reordered or run together.
  `P28.S1` is the one slice that is independent of the chain (server only) and runs first because `P28.S6`
  consumes its payload. (P28.DECOMP)
- **Doc node URL form (open item 1) — additive, and the member link is unchanged.** `server/graph_api.py`
  emits **`canonical_path` beside the existing `url`** on every doc node (`null` when the tenant has no slug
  or the row does not own its pretty path); `url` stays `/documents/{id}`. The engine **prefers
  `canonical_path` on the public graph** (where `publicBase` is set) and keeps `/documents/{id}` on the
  member graph. This satisfies intent's "canonical_path node URLs" where it matters (the stranger's link),
  satisfies R05 §4.6's member cell verbatim, and satisfies R05 acceptance check 8 literally — "the read link
  points inside `/@{org}`", which `/@{org}/{project}/{slug}` does. It also repairs a factual error in the
  signed record: §4.6's public cell `{publicBase}/documents/{id}` **is not a route that exists** (the app has
  `(public)/documents/[id]` and `(public)/[org]/[project]/[slug]`; `/@{org}/documents/{id}` would resolve as
  project `documents` and 404). Reported, never fixed by editing round 05 — the P27 precedent for card 04's
  stale annotation. The residual member-side choice is an operator question (below), defaulting to
  "member keeps `/documents/{id}`". Server half: **S1**. Engine half: **S6**. (P28.DECOMP)
- **`graph-r5.css` loads from `globals.css`, and it lands in `P28.S4` (open item 2).** R05 §1 names the
  component as the import site; R06 §1 — the later signed round — states the cascade with `graph-r5.css`
  between `kb-console-r4.css` and `kb-docview.css`. They are reconciled by loading it from `globals.css` at
  that position: same rules, same order, deterministic, and it is the **only** site that makes §3's shell
  line `.kb-app--public .kb-app-layout { grid-template-columns: minmax(0, 1fr) }` reach the non-graph public
  pages (the document views round 06 rebuilds), which a component-scoped import cannot. Because round 04's
  `public-shell.tsx` change is what *creates* that trap, **S4 creates `graph-r5.css` verbatim and adds its
  import in the same slice as the trap** — a sequencing choice, not a design change: the file is copied
  byte-for-byte from R05 §3 into its record-stated path. Consequence S4 and S6 must both know: between S4
  and S6 the graph plate is sized by round 05's rules while the engine is still round 04's, so the graph page
  looks transitional (the legend may vanish on a small plate before the dock exists). That is expected, is
  **not** a defect to fix in S4, and S6 is what closes it. (P28.DECOMP)
- **D18 is absorbed, not promoted (open item 3) — its two halves already sit inside two slices.** Verified
  today: `/login` honours no `next` param (`login/page.tsx` → `LoginForm` → `credentials-form.tsx` hard-codes

- **The batched round-trip guard is exact, and the pretty path has one builder.** `P28.S1` verified the
  prefix argument in the source rather than assuming it: `db.find_latest_document_by_slug` (`db.py:294`)
  resolves `(project, slug)` with `ORDER BY date DESC, id DESC LIMIT 1`, and the single windowed
  `db.list_documents` (`:367`) `_build_graph` uses orders by the **same** total order (`id` is unique, so it
  is total) with `OFFSET 0` — the window is therefore a **prefix** of the global newest-first order, and the
  **first** row seen for a `(project, slug)` while walking it in order is exactly the row that primitive
  would return. The `project` / `projects` narrowing filters by **project name**, which is part of the key,
  so they remove a group *whole* and can never hide its newest row; truncation at `MAX_DOC_NODES` drops only

  extra queries instead of up to 2000 per graph load, and no fallback path exists. The format string is
  **not** re-derived: `graph_api` imports `documents_api._canonical_path` (the module already imports
  `_resolve_project_name` and `get_conn` from there, so the seam is the established one) — one builder, so a
  future change to the pretty path shape cannot fork. (P28.S1)
