## 2. The three open items — how they were resolved

### 2.1 Doc node URL form (spot-checked against the code)

Read: `server/graph_api.py:60-135` (`build_tenant_graph`, the node dicts, `"url": f"/documents/{d['id']}"` at
`:87`), `:160-208` (`_build_graph`, `_graph_canonical_path`), `server/documents_api.py:237-330`
(`_canonical_path`, `_owns_its_canonical_path`, `_document_canonical_path`), `server/db.py:367-387`
(`list_documents` → `SELECT documents.*`, so `project` and `slug` are already in the window).

Resolution: **additive** — `canonical_path` beside `url` on each doc node, `url` unchanged; the engine
prefers `canonical_path` **only on the public graph** (where `publicBase` is set) and keeps `/documents/{id}`
on the member graph. Three reasons beyond the plan's:

1. It satisfies R05 acceptance check 8 **literally** — "the read link points inside `/@{org}`" — because
   `canonical_path` *is* `/@{slug}/{project}/{slug}`.
2. R05 §4.6's public cell, `{publicBase}/documents/{id}`, **is not a route that exists**. The app's routes
   are `(public)/documents/[id]`, `(public)/[org]/[project]/[slug]`, `(public)/[org]/graph`,
   `(public)/graph/[org]` (full list from `find web/src/app -name page.tsx`); `/@{org}/documents/{id}` would
   match `[org]/[project]/[slug]` with project `documents` and 404. So the literal reading is unbuildable and
   the canonical reading is the only one that yields a working stranger link. Reported as a record error —
   **never** fixed by editing round 05 (the P27 precedent for card 04's stale annotation).
3. Preferring `canonical_path` on the *member* graph would send a member to the **public** view of their own
   document (no copy-link, no delete), which §4.6 says explicitly stays unchanged. That residual is the one
   genuine operator choice, so it went on `## Operator Questions` with the default stated.

Trap recorded for S1: `canonical_path` is gated by `_owns_its_canonical_path` (the P25.F1 round-trip guard),
one `find_latest_document_by_slug` read per document, against up to `MAX_DOC_NODES = 2000` nodes — S1 decides
batch-or-narrow and records it. R05 §4.6 also relieves S1 of any visibility field ("the public graph endpoint
already filters to public projects").

### 2.2 Where `graph-r5.css` loads

R05 §1 names `graph-canvas.tsx` as the import site; R06 §1's load-order block puts the file between
`kb-console-r4.css` and `kb-docview.css`. The deciding fact is §3's shell line
`.kb-app--public .kb-app-layout { grid-template-columns: minmax(0, 1fr) }` — round 05's own §9 says round 04
"left the two-column rail grid in place, so a public page at a desktop width put main in the 15rem rail
track". A component-scoped import would leave every **non-graph** public page (exactly the document views
round 06 rebuilds) broken at desktop widths.

Resolution: load it from `globals.css` at R06's stated position — same rules, same order, deterministic
(today `graph.css` / `graph-tokens.css` are component-imported at `graph-canvas.tsx:8-9`, which Next does not
order deterministically against `globals.css`) — and, because round 04's `public-shell.tsx` change is what
*creates* the trap, **`P28.S4` creates the file verbatim and adds the import in the same slice**. Copying a
verbatim record artifact into its record-stated path earlier than its own round is a sequencing choice, not
a design change, and it is what keeps the plan's "the round-04 apply slice must not ship the trap unfixed".

Named consequence (in the notebook for both S4 and S6): between S4 and S6 the plate is sized by round 05
while the engine is still round 04's, so the graph page looks transitional — expected, not a defect for S4
to fix, closed by S6.

Rejected alternatives: putting the one line in `kb-console-r4.css` or `kb-console-responsive.css` (both are
verbatim "Do not touch" records); a stray rule in `globals.css` (duplicates the rule once round 05 lands).
