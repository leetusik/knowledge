# do-whole-phase — delegating a slice, its verdict and the commit

- Delegated slices (decomposition, `research`, implementation, `fix`, review — every kind except `co-work`, whose round lifecycle stays inline but whose **drafting span (`design-drafter`), critique spans (`design-critic`, when a job's critique level asks for them) and mockup span (`slice-executor-high`, when the operator asked for one) dispatch exactly like these**): dispatch the executor via the Agent tool **as a background task** (the default — never pass `run_in_background: false`) and wait for its completion notification, doing nothing else in the meantime **except the optional read-only preparation for slice N+1 — the next slice only — described in the next bullet** — never run it synchronously inline in the main session, never write to the repo or move workflow state while it runs, and one **executor** at a time: wait for it to return before dispatching the next (read-only research is not an executor and does not count against that limit). **The one carve-out from one executor at a time is a design wave's spans:** one drafter per job at once, and a judge beside its job's next drafter pass — disjoint job folders, design spans only, all inside the one `co-work` slice.

The route table (resolve, pin, dispatch, record, Explore) is in `reference/dispatch.md`.

The executor does the slice's job against `plan.md`; it writes `result.md` (verdict block first), edits the phase notebook under its budget, and returns a structured verdict. Then trust the verdict: read it and the **head** of `result.md` (its verdict block is that return's durable copy — read further only on a verdict other than `done`, or when you want the detail), and run `python3 scripts/workflow.py validate` (state integrity only — do **not** re-run the slice's tests; the phase review validates all slices together). On `needs_operator`, set the slice `pending`, report, and STOP; on `blocked`, record the blocker and STOP; on `escalate` — or a failed/empty return from `slice-executor-mid` (an escalation with no findings) — append an `## Escalation: mid → high` section to the slice's `plan.md` with the executor's `escalation` findings, resolve with `executor-route <slice_id> --retry`, pin its lines under that section, re-dispatch the slice to `slice-executor-high`, and record the second attempt (present the revised plan for approval only in `gate` mode — in the default re-dispatch straight away; max 1 escalation per slice); on a failed or empty return from `slice-executor-high`, treat the slice as not done and STOP. A `done` verdict proceeds.

- Commit at every clean slice boundary by default, following the Commit Convention (do not branch unless the operator asks; never push. A phase the operator asked into a worktree already has its branch — that branch *is* the worktree they asked for, so its slice commits land on `phase/P<N>-<slug>` without asking again; every other phase's land on the current branch. Pushing still needs asking: the `parallel-phase` integration merges locally by default, and its push → PR variant runs only when the operator asks, each push still passing the permission prompt). Commits are the orchestrator's job — the executor never commits. **Attribute the slice commit to the model that did the work:** its trailer is `Co-Authored-By: <attribution> <noreply@anthropic.com>`, `<attribution>` being the `attribution=` line of the dispatch that produced the work — equivalently the name for the `model:` its verdict block records; a slice done in two attempts goes to the model that completed it. Commits carrying only your own work (phase creation, a gate declaration alone, a verdict record) are attributed to the session's model as before; never carry over another session's trailer.
