# The route table — resolve, pin, dispatch, record, limits, Explore

Shared by `do-next-slice` and `do-whole-phase` (one source, copied into both skills at build).

**Dispatch through the engine's route table — the decision is the engine's, never yours:** kind first (decomposition, `research` and review always route to the high row, by **kind**, whatever their `risk` says; a `co-work` mockup span too), then `risk` (exactly `low` → the mid row, the default — real code, multi-file work, `docs` and `qa` included, as long as `plan.md` pins the approach; anything else → the high row), then attempt (every second attempt → high). (1) **Resolve:** once `plan.md` is written (and after `start-slice`), run `python3 scripts/workflow.py executor-route <slice_id>` — add `--retry` on a second attempt — and `python3 scripts/workflow.py executor-route --explore`. **Bump up, never down:** when the plan you write hits a named trigger (open design, a core invariant, an unlocated root cause, a wide blast radius) on a slice rated `low`, set `risk` to `high` in its `slice.json` (that one field; `python3 scripts/workflow.py rebuild` regenerates the table), say why in `plan.md`, and resolve again; never lower a rating. (2) **Pin:** append a final `## Dispatch` section to the slice's `plan.md` holding the slice form's lines verbatim (`route=` … `attribution=`) plus the `--explore` form's `model=` / `effort=` renamed `explore_model=` / `explore_effort=` — the executor copies its `model` / `effort` into its verdict block from there and takes its `Explore` lookup model from it; on a retry the new lines go under the `## Escalation: mid → high` section instead. (3) **Dispatch:** the Agent tool, as a background task, `subagent_type` = the `subagent_type=` line; pass `model` (the `model=` line, an Agent-tool alias) only when `pass_model=yes`, and `effort` (the `effort=` line) only when `pass_effort=yes`. A `fallback=` line is informational (`model=` already carries the fallen-back model); relay every `warning=` line to the operator in your report — it means the per-dispatch value will not take effect on this machine. **Every dispatch prompt starts with a `slice: <id>` line** (then the slice folder and the repo root) — the meter attributes the span by it. (4) **Record:** after the completion notification — before `finish-slice`, so the record rides in the slice's commit — run `python3 scripts/workflow.py record-dispatch <slice_id> --verdict <done|escalate|needs_operator|blocked|failed> [--attempt 2]`, one call per slice dispatch; a failed or empty return is `--verdict failed`. That is the whole record: what a span ran on, how long it took and what it cost are metered from Claude Code's transcripts by `dispatch-summary`, so design spans (drafter, critic, judge) are metered, never recorded by hand. (5) **Usage limits:** a span that stops on a usage or rate limit is a limit hit, not a verdict — record nothing for it yet. After Claude Code's own auto-continue of the main thread, resume the span with `SendMessage` (it keeps its full history), or else re-dispatch it from what is on disk. A limit whose error gives no reset time is `needs_operator`: set the slice `pending` (`--stop-kind limit --on-words "<their go-ahead resumes the span>"`) and stop. Never stagger a wave to dodge a limit. (6) **Explore for lookups:** your planning research uses the project `Explore` agent (`subagent_type: Explore`) at the `--explore` form's `model` / `effort` (haiku @ xhigh; `sonnet` under a loopback proxy), upgraded per call — `model: sonnet` or `model: opus` — for a lookup that needs judgment (why, a trade-off, an audit); it locates and summarizes, never decides, and its brief is advisory input to your plan, never a plan (`Plan`-type agents and inline reads stay available). `/executor-route` shows the resolved table and `python3 scripts/workflow.py dispatch-summary` what each slice really cost — the main thread beside its spans, metered from the transcripts; `executors.toml`'s per-row `[claude.<row>]` overrides are the operator's knob — there are no presets.
